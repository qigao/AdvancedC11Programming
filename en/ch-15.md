# Chapter 15: Integrating CMeta: From Declared Facts to Reliable Execution

Earlier chapters established conditions for macro expansion, call adaptation, graph transformation, and asynchronous execution. This chapter applies them to a bounded service that returns the sum of even squares. A complete ordinary C program comes first, followed by contract binding, reusable execution, and asynchronous handoff, preserving the relevant preconditions at each step.

## 1. A Standalone Baseline

The program accepts at most one thousand integers in `[-100, 100]`. Success returns the sum, including zero for empty input. Invalid arguments or values preserve the prior response. Request, response, and nonempty input arrays must be valid objects, with response storage disjoint from input.

~~~c
#include <stddef.h>
#include <stdio.h>

enum {
    BOOK_OK = 0,
    BOOK_INVALID_ARGUMENT = 1,
    BOOK_OUT_OF_RANGE = 2,
    BOOK_MAX_ITEMS = 1000
};

typedef struct BookRequest {
    const int *values;
    size_t count;
} BookRequest;

typedef struct BookResponse {
    long total;
} BookResponse;

int book_score(const BookRequest *request, BookResponse *response)
{
    if (request == NULL || response == NULL)
        return BOOK_INVALID_ARGUMENT;
    if (request->count > BOOK_MAX_ITEMS ||
        (request->count != 0 && request->values == NULL))
        return BOOK_INVALID_ARGUMENT;

    long total = 0;
    for (size_t i = 0; i < request->count; ++i) {
        int x = request->values[i];
        if (x < -100 || x > 100)
            return BOOK_OUT_OF_RANGE;
        if (x % 2 == 0)
            total += (long)x * x;
    }

    BookResponse next = { .total = total };
    *response = next;
    return BOOK_OK;
}

int main(void)
{
    const int values[] = {1, 2, 3, 4, 5, 6};
    BookRequest request = {
        .values = values,
        .count = sizeof(values) / sizeof(values[0])
    };
    BookResponse response = { .total = -1 };
    if (book_score(&request, &response) != BOOK_OK)
        return 1;
    printf("%ld\n", response.total);
    return response.total == 56 ? 0 : 1;
}
~~~

Compiled as C11, it prints `56`. The sum uses `long` and the function returns an independent `int` status. Mixing the business value with status would make valid values and failure interpretation harder to distinguish.

## 2. Correctness and Failure Boundaries

Before iteration `i`, processed values are within the admitted domain, `total` is their even-square sum, and `0 <= total <= 10000i`. This holds initially. An out-of-range value returns before modifying the response. An odd value leaves the sum unchanged; an even value adds at most ten thousand, preserving the invariant.

With `i <= 1000`, the total is at most ten million, within C11's guaranteed `long` range. Only the final assignment publishes the result. Input `{2, 101}` therefore fails while retaining the previous response instead of publishing four. Empty input successfully commits zero.

The proof concerns synchronous local execution. Input storage must remain valid and race-free for the whole call; `const` does not freeze an array mutated by another thread. Every adapter must preserve these conditions or establish an equivalent owned copy at its boundary.

## 3. From C Types to a Shared Call Contract

With only `main` as a caller, the baseline is complete. External binding, generated mocks, or dynamic publication create reasons to describe `BookRequest`, `BookResponse`, and `book_score` in CMeta. The description records an input-borrowed request, output-borrowed response, and value status result.

| Fact | CMeta use | Remaining application contract |
|---|---|---|
| Request and response C types | Data descriptions and native ABI | `values` addresses `count` live elements |
| Parameters and return type | FunctionDesc and FunctionAbi | Domain, count bound, status meaning |
| Uniform invocation | Explicit exact thunk | Storage type, alignment, lifetime |
| Provider context | Borrow or interface instance | Lifetime and concurrent access |

Reflection of a pointer does not infer its array-length relationship. The data model must relate `values` to `count` or use a sequence representation supported by the generator. Reflecting two fields alone does not produce a safe wire decoder. Type and ABI registration also follow Chapters 2 and 3's finite rules.

The adapter argument reuses Chapter 3: rejected admission does not call the target; successful admission with valid storage calls the concrete function once. The target's result proof additionally relies on its numeric-domain checks.

## 4. Logical Service and Native Representation

The logical request can specify up to one thousand bounded integers, a sum response, and distinct argument/domain errors. This sequence contains no native pointer. DataBind projects it into local storage with explicit ownership.

~~~text
admit_score_service:
    resolve the logical request, response, and error contract
    match the generated native layout and exact function ABI
    require a supported bounded sequence representation
    compile ingress, egress, and error mappings
    retain descriptor/code owners for the service lifetime
~~~

This is integration-design pseudocode, not a claim that every current HTTP backend supports this sequence. Chapter 8 records the pinned CHttp structured-input/output limits. Unsupported forms fail before mount, while the ordinary C function remains available for local use and baseline testing.

Repository injection in `get_user` and sequence storage here illustrate the same boundary: the contract states exchanged data; native binding specifies dependencies and ownership. A C parameter list is not mechanically a set of network fields.

## 5. A Reusable Computation Plan

Repeated evaluation and comparison of multiple pipelines can justify Filter, Map, and seeded Reduce representation. Domain checking remains necessary, perhaps at input admission; PURE/TOTAL metadata does not authorize removing it.

~~~text
prepare_computation:
    describe is_even: int -> bool
    describe square: int -> long over the admitted domain
    describe sum: (long, long) -> long over bounded nonnegative totals
    build and validate the typed graph with zero seed
    normalize and apply only authorized rewrites
    compile the explicitly selected supported Plan

evaluate_computation:
    validate input count and every input value
    borrow or own the accepted array for the entire evaluation
    execute the reusable plan
    commit one result or report failure
    destroy the owned result at its documented boundary
~~~

Seeded reduction matches the baseline's empty-input zero. Choosing Chapter 5's unseeded Reduce instead requires explicitly interpreting its absent result as zero in the caller and including that decision in comparison. The full pipeline containing Reduce exceeds Chapter 7's pinned Direct Filter/Map support.

The plan preserves type relationships and evaluation meaning; the baseline establishes numeric bounds. Together they support result comparison. Adding logs or managed resources changes the observation model, so a value-only proof no longer authorizes deleting, reordering, or retrying those calls.

## 6. Obtaining Valid Input for Deferred Work

Synchronous borrowing of a stack array is safe while the call remains within its lifetime. Copying `BookRequest` into a task copies only a pointer and count; the array may disappear before execution. Deferred work needs an owned bounded frame or explicit retention of the input owner.

~~~text
submit_score(request):
    validate count and values
    acquire an owned bounded frame
    copy the admitted array into the frame
    store result and completion state in that frame
    submit run/cancel/finalize callbacks
    if rejected:
        release the caller-owned frame
    if accepted:
        let the terminal task path release it exactly once
~~~

The ownership invariant assigns the frame to the caller before submission and after rejection, then to terminal task cleanup after acceptance. Last access precedes release. A run callback can publish an independently owned response or use a receiver with a specified retention protocol; it cannot return a pointer immediately invalidated by finalize.

If execution or cleanup comes from a Plugin, its lease covers finalize. Chapter 10's task ledger and Chapter 13's unload order jointly constrain this path. Successful post means neither completed output nor a context guaranteed still live at return.

## 7. Continuous Input Needs a Reactive Protocol

A batch request has a finite result; a continuous source may temporarily lack data. This introduces Chapter 9's VALUE, WAIT, DONE, and ERROR, demand credits, and wait registration. WAIT is an observation; registration and final suspension must prevent lost wakeups. A callback token alone cannot retain its storage.

With demand two, suppose the source produces one and then two. Filter delivers only two, leaving demand one. WAIT consumes no remaining credit, and waking merely requests further progress without adding credit. Only another actual downstream output reduces demand to zero. With terminal Reduce, its result rather than each input consumes downstream output credit.

Persistent connection control may additionally need Machine and Actor. The scoring service does not require an Actor merely because it is asynchronous. Add those objects when typed events, serial mutation, retained producer capabilities, and shutdown races become real requirements.

## 8. Turning Integration Claims into Checks

| Case | Required behavior | Comparison |
|---|---|---|
| `{1,2,3,4,5,6}` | Sum `56` | Ordinary C, adapter, supported Plan |
| Empty input | Success and zero | Explicit unseeded-reduction handling |
| `{2,101}` | Failure, unchanged response | No partial binding or execution publication |
| One thousand `100` values | Ten million without overflow | Capacity and domain limit |
| Task FULL | No target call; caller cleans frame | Rejection ledger and lifetime |
| Cancellation after acceptance | Exclusive run/cancel, one finalize | Executor protocol |
| Live Plugin borrow | Unload rejected | Real shared-library test |

Compare direct calls, thunks, Invokables, Plans, and workspaces using the same inputs and admitted domains, only for shapes each supports. Report preparation, single and repeated execution, peak storage, and code size. Baseline correctness and Lean theorems are not performance measurements.

## 9. A Reusable Method

Each mechanism addresses a specific gap: macros consolidate declarations; CMeta exposes native facts; DataBind compiles external/native mappings; CFlow records compositions; runtime objects maintain state that cannot be fixed at build time. Preserve the ordinary C baseline, define inputs, outputs, failures, and ownership, then specify the transformation or state algorithm.

Reason about the same objects the algorithm manipulates: prefix invariants for loops, parameter reconstruction for binding, initialized sets for resources, and phase partitions for tasks. Existing formal theorems establish their model conclusions. Compilation, installation, concurrency, and measurement validate the remaining implementation conditions.

## 10. Summary

CMeta makes shared facts available to checked declarations and descriptions, while execution still follows concrete C types, lifetimes, and resource contracts. Reliable integration aligns the boundaries: conversion establishes domains, adapters preserve calls, plans preserve computation, and runtime instances maintain state and single cleanup. New behavior at any layer requires corresponding changes to examples, arguments, and verification.
