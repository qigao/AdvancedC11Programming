# Chapter 13: CMeta Engineering Boundaries: Type Identity, ABI, and Shared Libraries

Static descriptors can have separate representations in different translation units and shared libraries. Code may also be unloaded while a caller still retains its function pointer. CMeta identity, Plugin leases, and ABI checks therefore need real compilation, linking, and loading evidence. This chapter develops a multi-file example and a complete retirement sequence.

## 1. Independent Descriptors in Two Translation Units

A **translation unit** (TU) is a source file after preprocessing. A header's `static` object has internal linkage, producing a separate representation in each including source file. This `user_meta.h` isolates identity with a one-field type; it is not Chapter 8's complete service-response `User`.

~~~c
#ifndef BOOK_USER_META_H
#define BOOK_USER_META_H

#include <cmeta/cmeta.h>

typedef struct BookUserId {
    int id;
} BookUserId;

static const cmeta_type_identity BookUserId_identity =
    CMETA_TYPE_ID_ATOM_INIT("book.UserId.v1");

static const cmeta_type_desc BookUserId_desc = {
    .name = "BookUserId",
    .size = sizeof(BookUserId),
    .align = _Alignof(BookUserId),
    .kind = CMETA_T_OBJECT,
    .pointee = NULL,
    .traits = NULL,
    .identity = &BookUserId_identity
};

static inline const cmeta_type_desc *book_user_type(void)
{
    return &BookUserId_desc;
}
#endif
~~~

`tu_a.c` and `tu_b.c` expose their descriptions:

~~~c
/* tu_a.c */
#include "user_meta.h"

const cmeta_type_desc *type_from_a(void)
{
    return book_user_type();
}
~~~

~~~c
/* tu_b.c */
#include "user_meta.h"

const cmeta_type_desc *type_from_b(void)
{
    return book_user_type();
}
~~~

`main.c` compares meaning and returns zero on success. The public requirement is not that addresses must differ, but that semantic comparison remains correct when representations are independent.

~~~c
#include <cmeta/cmeta.h>

const cmeta_type_desc *type_from_a(void);
const cmeta_type_desc *type_from_b(void);

int main(void)
{
    const cmeta_type_desc *a = type_from_a();
    const cmeta_type_desc *b = type_from_b();
    return cmeta_type_equal(a, b) &&
           cmeta_type_identity_equal(cmeta_type_identity_of(a),
                                     cmeta_type_identity_of(b))
           ? 0 : 1;
}
~~~

`traits = NULL` declares no additional capabilities. Algorithms requiring copy, destruction, or comparison traits need further admission. Identity and algorithm capabilities are separate checks.

## 2. Equality Depends on the Object

Chapter 2's type identities combine atoms, pointers, qualifiers, and generic applications. Comparing finite identity trees recursively establishes structural equality when corresponding leaves and constructors agree. Layout and other descriptor contracts still require their appropriate checks; a stable string cannot excuse incompatible representations.

| Object | Relevant facts |
|---|---|
| TypeDesc | Semantic comparison through `cmeta_type_equal` |
| Type identity | Structural `cmeta_type_identity_equal` |
| FunctionDesc | Names, parameters, result, flags, and behavior contract |
| FunctionAbi | Native carriers and associated function contract |
| Callable | Authoritative execution representation and captures |
| DataBind operation | Qualified identity, version, operation, and request/response relationships |

A raw C target may acquire different generated wrappers in different TUs. If the canonical raw target is authoritative, wrapper-address differences alone should not establish different calls. Adapter representations instead follow their adapter-and-capture rules. `bind(multiply, 10)` and `bind(multiply, 20)` are different callable values even with identical code entry points.

FunctionDesc equality proves neither identical machine-code behavior nor FunctionAbi equality. Optimizer duplicate detection, AOT matching, and Plugin admission depend on these distinctions.

## 3. Building Through an Installed Package

Place the four files above in an independent directory with this `CMakeLists.txt`:

~~~cmake
cmake_minimum_required(VERSION 3.20)
project(book_identity C)

find_package(Salts CONFIG REQUIRED)

add_executable(book_identity main.c tu_a.c tu_b.c)
target_compile_features(book_identity PRIVATE c_std_11)
target_link_libraries(book_identity PRIVATE Salts::CMeta)
~~~

Install the pinned SDK into a separate prefix and configure this project through its installed package. The example exercises public headers, configuration, and link targets together. Adding private source-tree includes would conceal packaging defects.

Salts remains the actual package and CMake namespace. Prose uses CMeta, CFlow, and CMeta Plugin; exact exported target names are `Salts::CMeta`, `Salts::CFlow`, and `Salts::Plugin`.

## 4. Executable Code Has a Lifetime

A **DSO**, or dynamic shared object, is a dynamically loaded library such as an ELF shared object; a Windows DLL serves the corresponding role. Descriptors, trait operations, thunks, and vtables retained by the host may point into it. Keeping a heap object alive does not keep its executable targets loaded.

`cmeta_plugin_registry_acquire` obtains a lease from a started module, covering borrowed manifests, exports, descriptions, and code. A **lease** is a lifetime credential, not an automatically expiring network lease. Load with `cmeta_plugin_registry_load` and start with `cmeta_plugin_registry_start` first. This fragment requires `<salts/plugin.h>`, a valid registry, and a started reference:

~~~c
cmeta_plugin_lease lease = {0};
const cmeta_plugin_manifest *manifest = NULL;
cmeta_plugin_status status = cmeta_plugin_registry_acquire(
    &registry, ref, &lease, &manifest);
if (status != CMETA_PLUGIN_OK)
    return status;

/* Use manifest and exports while lease remains live. */
~~~

After success, the outer owner completes use and cleanup in the next section’s order before releasing the lease. Failed acquisition does not permit manifest use; error cleanup releases only resources already acquired and preserves diagnostics. Registry setup and shutdown belong to the surrounding module-control code and are omitted here.

## 5. Deriving the Unload Order

Suppose a returned object still needs a Plugin-provided destroy operation. Releasing the last lease and unloading before destroying that object jumps into invalid code, even if the business function returned long ago. The lease interval must include binding, invocation, output, and final cleanup.

~~~text
retire_plugin:
    prevent the application from starting new uses
    request plugin stop, closing new lease admission
    finish accepted calls and callbacks under their live leases
    destroy dependent native values, adapters, and plans
    release each acquired lease and check the release result
    establish plugin quiescence through its lifecycle protocol
    unload only after no leases or lifecycle callbacks remain
~~~

**Quiescence** means relevant users and callbacks have finished and can no longer access the resource. Active leases block unloading, but zero leases do not replace lifecycle checks. The pinned runtime also requires an unloadable lifecycle state and no active lifecycle callbacks.

Successful release consumes and clears a lease; failure leaves its value unchanged. Callers must check that result. A reference generation distinguishes recycled module identities, but these checks still require valid registry handles. They do not authorize dereferencing an unloaded manifest.

## 6. Exact ABI Epochs

An **application binary interface** (ABI) covers calling conventions, layouts, symbols, and cross-module contracts. An **ABI epoch** identifies a generation of those contracts. This CMeta Plugin version admits only the exact current epoch and manifest/export layouts, without older-version negotiation.

~~~text
admit_manifest(manifest):
    require struct_size equals the current layout size
    require abi_version equals CMETA_PLUGIN_ABI_VERSION
    validate every exposed export and its contract
    reject before consuming incompatible descriptor pointers
~~~

A `struct_size` field does not imply readable-prefix compatibility. Other provider interfaces may explicitly support a minimum prefix and optional tail fields; that rule cannot be projected onto Plugin's exact-epoch contract. Equal epochs also do not replace type, ownership, and export validation.

The runtime contract is in [plugin/include/salts/plugin.h](https://github.com/qigao/salts/blob/a650262031e9b3e5f11a227a7911a75db9ae1fb8/plugin/include/salts/plugin.h). Its path retains the package name while public symbols use `cmeta_plugin_*`.

## 7. Visible Fields and Configuration

| Field category | Permitted use |
|---|---|
| Configuration rows and public result fields | Initialize or inspect as documented |
| Graph/Plan read-only introspection | Diagnose and verify; mutate through public APIs |
| Opaque handle `impl` | Zero-initialize and pass to APIs; do not dereference, serialize, or copy a live owner |

Compile-time configuration can affect ABI. CMeta's known-type universe differs from its callable-signature universe. Changes affecting signatures must be visible consistently to every relevant TU. Exported CFlow Machine limits should likewise reach consumers through installed targets. Undiagnosed inconsistent configuration remains unsupported rather than something runtime guessing can repair.

`_Generic`, static type assertions, and macro generation need call-site C type information and belong in headers. Graph validation, identity comparison, queues, and plan compilation can live in compiled libraries. This division retains static checking without duplicating the entire runtime into every TU.

## 8. Generated Artifacts and Toolchain Checks

Signature and policy tables derived from formal models should be generated from their authoritative sources and checked with the generator's validation mode. Ordinary C users can consume committed output without running Lean; release maintainers must still detect drift.

Compiler extensions are public prerequisites. Native type queries, cleanup attributes, and section layout require Chapter 1's capability checks. An unavailable capability requires explicit rejection or a separately documented interface, not an unchecked cast pretending to preserve the original guarantee.

| Claim | Verification |
|---|---|
| Identity across TUs | Independent representations and mismatch cases |
| Contract across a shared library | Real host/library with epoch and layout rejection |
| Borrows block unsafe unload | BUSY under a live lease; unload after cleanup and quiescence |
| Complete package | Independent consumer using only installed headers and exported targets |
| Memory and callback lifetimes | Failure paths, controlled concurrency, and sanitizers |
| Generated facts agree | Generator checks and corresponding formal-project validation |

Comparing `sizeof` alone misses calling conventions, symbols, enum meaning, ownership, and shutdown. Changing FULL into silent dropping changes a caller-visible contract even if layout is unchanged. Snapshot and combined-build limitations remain recorded in `SOURCE_SNAPSHOTS.md`.

## 9. Summary

Semantic identity permits independent representations of one contract; ABI checks still constrain layouts, carriers, and configuration. Plugin leases cover code, data, and cleanup, while unloading additionally requires lifecycle quiescence. Independent TUs, real shared libraries, and installed consumers verify different boundaries that one source-tree link cannot establish.
