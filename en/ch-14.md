# Chapter 14: Choosing Techniques: When Ordinary C Is Sufficient

Descriptors, generators, and runtime objects introduce maintenance costs. Choosing a CMeta technique requires comparing the duplicated facts it removes with the type, capacity, lifetime, and build constraints it adds. Fixed loops, individual callbacks, internal functions, and static linking provide concrete comparisons for deciding which abstractions to retain.

## 1. Decision Tree: Ask Whether Abstraction Is Needed at All

~~~text
problem appears
    |
    v
Can ordinary C express it clearly?
    |
   yes
    |
    v
Is stable knowledge duplicated across modules/backends?
    |
   no -----------------> keep ordinary C
    |
   yes
    |
    v
Can that knowledge be finite / explicit / bounded?
    |
   no -----------------> keep it local or runtime-specific
    |
   yes
    |
    v
Does one shared semantic object remove real maintenance/correctness risk?
    |
   no -----------------> keep ordinary C
    |
   yes
    |
    v
introduce the smallest semantic object
~~~

### 1.1 Choose the Smallest C Mechanism Before Adding a Semantic Object

The division of labor from Chapter 1 becomes a restraint rule here:

~~~text
Can a normal C function express the behavior?
        |
       yes
        v
normal function / static inline

Need tokens, declarations, identifiers, or finite schema replay?
        |
       yes
        v
finite macro / PP kernel

Need compiler-native knowledge?
        |
       yes
        v
capability-gated compiler abstraction

Need stable meaning shared by independent consumers?
        |
       yes
        v
canonical Reflection / semantic descriptor
~~~

Reject this path:

~~~text
macro
  -> more macro
  -> hidden behavior
  -> hidden allocation / dispatch / ownership
~~~

Prefer this default shape:

~~~text
schema / facts
    |
    v
small finite macro
    |
    v
static-inline typed facade
    |
    v
shared ordinary-C implementation
~~~

Macros handle token and declaration generation that a C function cannot express. static inline handles typed behavior, normal evaluation rules, and direct-call surfaces. Reflection appears only when stable meaning must be shared by independent consumers. Do not use a macro to replace a type-checked C function merely because it can encode the behavior; and do not turn a direct C call into runtime Reflection dispatch merely because metadata exists.

## 2. Four Cases Where Ordinary C Wins

### 2.1 One Fixed Pipeline: Keep the Loop

~~~c
size_t copy_even_squares(
    const int *xs,
    size_t n,
    long *out)
{
    size_t m = 0;

    for (size_t i = 0; i < n; ++i) {
        int x = xs[i];

        if ((x & 1) != 0)
            continue;

        out[m++] = (long)x * x;
    }

    return m;
}
~~~

With one pipeline, one call site, no dynamic composition, rewrite, verification, or alternate backend, Graph removes no new stable duplication.

**Keep the loop.**

### 2.2 One Callback: Keep the Function Pointer

~~~c
typedef void (*done_fn)(void *user);

void request_start(done_fn done, void *user);
~~~

If the callback is not stored across a complex lifetime, composed, reflected, or optimized, a Callable object is unnecessary.

### 2.3 One Internal Function: Do Not Add an IDL

~~~c
static int
lookup_user(
    UserRepository *repo,
    uint64_t id,
    User *out);
~~~

If it is directly called inside one binary with no HTTP, RPC, Plugin, WASM, generated Mock, or external contract, message/service/component/databindc add no value. IDL is justified by **the same logical contract repeated across boundaries**, not by the existence of a function.

### 2.4 One Link-Time-Known Implementation: Do Not Add Plugin

~~~cmake
target_link_libraries(app PRIVATE image_codec)
~~~

If the implementation is unique, known at link time, and never dynamically discovered, replaced, or unloaded, direct linking is simpler than loader + registry + manifest + lease + quiescent unload.

## 3. Counterexample Lab: Six Dangerous Forms of “Convenience”

### 3.1 One Similarity Immediately Becomes a Meta DSL

~~~c
int user_age(const User *u)
{
    return u->age;
}

int order_count(const Order *o)
{
    return o->count;
}
~~~

Designing FieldGetter / GenerateAccessor / Reflect / GenericInvoke here abstracts **current code shape**, not stable knowledge. Field Metadata becomes justified only when serializer, binder, UI, query, and other independent consumers repeatedly maintain the same field schema.

### 3.2 Descriptor Pointer Becomes Semantic Identity

Wrong:

~~~c
if (a == b) {
    /* same type */
}
~~~

This may work in one TU. Across Multi-TU / DSO boundaries, one Pair<int,long> may have several descriptor objects. Address answers “where is this representation object?” rather than “what semantic type is this?” Use stable ids, constructor identity, and structural arguments.

### 3.3 Oversized Inline Capture Secretly Allocates

Wrong policy:

~~~text
capture > inline_capacity
    ↓
secret malloc
    ↓
API still looks like bounded value semantics
~~~

This silently changes copy, destroy, failure, lifetime, threading, and ABI semantics. The choice must be explicit:

- TOO_LARGE;
- explicit heap-backed callable;
- caller-owned external context.

Hidden convenience that changes ownership is semantic drift.

### 3.4 A Full Queue Automatically Grows

Wrong policy:

~~~text
queue full
    ↓
realloc / linked-list growth
    ↓
keep accepting
~~~

When producer rate exceeds consumer rate, this hides backpressure and turns a local FULL result into later memory, latency, and OOM failure. The primitive should report:

~~~text
capacity exhausted
    ↓
FULL
~~~

Higher layers choose retry, drop, load shedding, or upstream backpressure.

### 3.5 Requested Execution Silently Falls Back

The application explicitly asks for parallel reduce, but reducer contract fails, Executor is FULL, or the backend is ineligible. Wrong behavior:

~~~text
parallel requested
    ↓ failure
quietly run sequentially
~~~

Even if the result is equal, latency, CPU topology, resource usage, deadlines, and benchmarks changed. Return UNSUPPORTED / FULL / INELIGIBLE and let the application choose fallback explicitly. Semantic equivalence does not imply operational equivalence.

### 3.6 Domain Semantics Leak into Core

Typical drift:

- RPC needs retry → retry policy enters Executor;
- Workflow needs compensation → compensation enters Machine;
- JSON needs field names → JSON syntax enters CMeta.

Ask:

1. Is this meaning domain-specific?
2. Does it repeat stably across several independent domains?
3. Is Core complete without it?

If it is domain-specific, keep it above Core. Reuse does not require ownership transfer.

## 4. Other Common Counterexamples

| Counterexample | Problem | Better direction |
|---|---|---|
| TypeFunction chases recursion/partial specialization | preprocessor becomes an uncontrolled compiler | finite relation rows |
| Everything Is Virtual | known interior keeps permanent indirect dispatch | dynamic boundary / static interior |
| Raw parser tokens enter business Stream | grammar tokens are not semantic values | parse → bind → semantic value |
| Lean proves ABI / wall-clock performance | evidence layer does not match the claim | toolchain / benchmark evidence |

## 5. Budget Cost and Evidence Together

A Core abstraction adds permanent maintenance obligations.

| Abstraction | Duplication removed | Long-term cost added |
|---|---|---|
| Generic | repeated type-instantiation facts | generated API / diagnostics |
| FunctionDesc | repeated native function metadata | descriptor ABI / ownership rules |
| Graph | repeated composition / analysis logic | IR + optimizer + qualification |
| DataBind IDL | repeated logical contracts | compiler + versioning + codegen |
| Plugin | dynamic capability publication | loader + lease + unload ABI |
| WASM | portable component ABI | host/guest lowering |
| Actor | concurrency admission/lifecycle duplication | mailbox/ref/generation protocol |

Each new claim also creates an evidence obligation:

| New claim | Required gate |
|---|---|
| generated syntax | compile-pass / compile-fail |
| semantic identity | Multi-TU / DSO tests |
| lifecycle | sanitizer / stress |
| rewrite | semantic theorem + differential test |
| public ABI | installed consumer |
| performance | benchmark |
| projection backend | end-to-end integration |

If neither the long-term cost nor the evidence budget can be justified, the abstraction is not ready for Core.

## 6. Static Interior, Dynamic Boundary

Do not turn everything into {self, vtable} merely for uniformity.

| Region | Examples |
|---|---|
| Dynamic Boundary | Publisher / Scheduler / plugin provider |
| Static Interior | known Graph stage / Plan instruction / direct target |

A dynamic interface is a boundary tool, not a universal object model. Known information should be consumed in the build/control plane so the hot path can return toward direct C.

## 7. Review Checklist

Before adding a Meta / Runtime abstraction, ask:

- [ ] Is there a Plain C baseline?
- [ ] Is the repeated thing stable knowledge or only code shape?
- [ ] Do at least two independent consumers need the same fact?
- [ ] Why is a module-local helper insufficient?
- [ ] Does identity survive TU / DSO boundaries?
- [ ] Are ownership, failure, and capacity explicit?
- [ ] Is there hidden allocation or silent fallback?
- [ ] Does dynamic dispatch enter an unnecessary hot path?
- [ ] Do failures happen as early as possible?
- [ ] Do theorem, toolchain, and benchmark evidence each match the claim?
- [ ] Can the abstraction be lowered away from the hot path?

If many answers are unclear, the right move is usually not “improve the abstraction.” It is **shrink the abstraction**.

## 8. Summary

Descriptors and generated code can reduce drift when independent consumers need the same stable facts. For a fixed loop, local callback, or single implementation, ordinary C often expresses the behavior fully, while extra objects expand capacity, failure, and lifetime obligations. Choose advanced techniques by comparing concrete code and verification costs, and retain explicit rejection of unsupported inputs. Hidden allocation, silent fallback, and unsupported performance promises change the contract callers can rely on.
