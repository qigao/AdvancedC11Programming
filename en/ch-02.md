# Chapter 2: Finite Metaprogramming: Generics, Structs, Traits, and Type Relations

Fields and parameters are often repeated across declarations, type checks, and reflection. CMeta's finite metaprogramming kernel unifies row extraction while each consumer retains its own meaning. Using `User`, this chapter develops field projection, generics, traits, and type relations without conflating them into a runtime type system.

A **tuple** is a positional token row such as `(int, id, flags)`, not a runtime container. A **projection** selects its type, name, or another component. All consumers must agree on positions; sharing macros alone does not ensure consistent declarations.

## 1. Finite Mapping and Separators

These are pinned entry-point shapes; ellipses denote omitted arguments:

~~~c
CMETA_PP_MAP(M, C, a, b, c)
CMETA_PP_MAP_N(3, M, C, a, b, c)

CMETA_PP_MAP_COMMA_N(...)
CMETA_PP_MAP_SEMI_N(...)
CMETA_PP_MAP_PREFIX_COMMA_N(...)
~~~

The edition's list mappings have explicit bounds of 0–16 items. Counted forms take arity from the caller; automatically counted forms additionally have empty-argument and toolchain conditions. Exceeding the limit is an unsupported declaration, not another runtime loop iteration.

For rows `(int, fd)` and `(size_t *, written)`, a prototype needs one separating comma, fields need terminating semicolons, and a call needs only names. This teaching algorithm separates punctuation from row content:

~~~text
project(rows, emit, separator):
    reject a row count outside the supported bound
    for i from 0 to row_count - 1:
        if i != 0: emit separator
        emit the projection of rows[i]
~~~

**Expansion argument.** After `i` rows, the output contains `i` projections and `max(i - 1, 0)` separators. A new noninitial row adds one separator and one projection, preserving the invariant. Thus an empty list has no separator and a nonempty list has no trailing comma. Actual preprocessing uses a finite macro family; the loop explains its expansion.

## 2. Token Relations, Native Types, and Semantic Identity

The preprocessor recognizes registered tokens rather than parsing all C types. After `typedef void nothing;`, a predicate for the literal token `void` need not recognize `nothing`. Distinguish three checks:

| Layer | Example | Question answered |
|---|---|---|
| Tokens | `CMETA_PP_IS_VOID(x)` | Does this token belong to the specified set? |
| Native compiler types | `CMETA_NATIVE_TYPEOF`, `CMETA_SAME_TYPE` | Are the C types compatible? |
| CMeta descriptions | `CMETA_TYPEOF(T)` | Which shared type description is selected? |

Empty variadic arguments also need a capability boundary. `CMETA_HAS_VA_OPT` gates corresponding zero-safe forms; strict C11 consumers without it use documented explicit counts. `CMETA_PP_UNIQUE` prevents local generated-name collisions, not cross-translation-unit type-identity collisions. A translation unit is a source file after preprocessing, including header expansion.

## 3. Generics Produce Concrete Types and Thin Wrappers

This fragment requires registered SDK generic kinds; unknown kinds must be rejected:

~~~c
cmeta_type(List, IntList, int);
cmeta_type(Vec, IntVec, int);
~~~

Generated calls retain concrete C names and parameter types. A **typed façade** checks and forwards while a shared implementation performs allocation, growth, or movement. This teaching shape uses illustrative `list_push_raw` and `raw` names, not a promised public entry point:

~~~c
static inline cmeta_status
IntList_push(IntList *self, int value)
{
    return list_push_raw(
        &self->raw,
        &value,
        sizeof(value),
        CMETA_TYPEOF(int));
}
~~~

The address of parameter `value` remains valid only during the call. To retain the element, the shared implementation must copy or transfer it according to the element contract before returning; it cannot retain the local parameter's address. Generated type checking does not remove lifetime obligations.

Inspect preprocessing output and object-file sizes across several instantiations to distinguish short per-type wrappers from duplicated large algorithms.

## 4. Generate Structure and Description from One Field List

The following are alternative definitions, not declarations to combine in one scope. A plain structure needs generated metadata only when consumers share its field facts.

~~~c
typedef struct User {
    int id;
    double score;
} User;
~~~

~~~c
cmeta_struct(User,
    cmeta_field(int, id)
    cmeta_field(double, score)
);
~~~

The same `cmeta_field` rows produce native fields and reflection information. Checks must use actual member types, offsets, and sizes. For object size `S`, field offset `o`, and field size `s`, first require `o <= S`, then `s <= S - o`. Computing `o + s` first can overflow before validation. A valid layout range does not prove initialized field values.

An existing type can retain its native definition and separately project selected fields:

~~~c
typedef struct Account {
    int id;
    double balance;
} Account;
~~~

~~~c
cmeta_reflect_data(Account, "app.Account",
    cmeta_field(int, id)
    cmeta_field(double, balance)
);
~~~

The projection neither takes ownership of `Account` objects nor authorizes a serializer to guess undescribed fields. Mismatches with the native declaration must fail at the appropriate checked boundary.

## 5. Traits Connect Capabilities to Callbacks

A **trait** describes a supported operation, such as equality or hashing. Maintaining capability bits separately from callbacks can claim hashing support while omitting its function. One row should generate both:

~~~c
cmeta_traits(User,
    (equal, user_equal),
    (hash, user_hash)
);
~~~

This fragment assumes correctly declared `user_equal` and `user_hash` callbacks. Generation can reject duplicate or unknown traits and incorrect signatures, but signatures cannot establish behavior laws. A hash table also requires `equal(a,b)` to imply `hash(a) == hash(b)`. Case-insensitive string equality paired with case-sensitive hashing is a counterexample with valid signatures.

## 6. Finite Type Relations Require a Unique Match

Some shared facts relate input types to a result type. These four rows form a finite table rather than an arbitrary implicit-conversion system:

~~~c
TypeFunction(CommonArithmetic,
    (int, int, int),
    (int, double, double),
    (double, int, double),
    (double, double, double)
);
~~~

~~~c
typedef TypeEval(CommonArithmetic, int, double) result_type;
~~~

The second fragment obtains `double`. The pinned macro emits a typedef named from input tokens, and `TypeEval` composes and references that name without runtime traversal. The token `int` and an equivalent typedef name do not automatically become the same key. This pseudocode states the mathematical requirement for a duplicate-free relation rather than the macro's execution mechanism:

~~~text
lookup(relation, left, right):
    matches = rows whose two input types match
    if matches is empty: reject unsupported input
    if matches contains more than one row: reject ambiguity
    return the sole row's result type
~~~

**Uniqueness argument.** A duplicate-free definition contains at most one row for each input pair. Requiring at least one establishes exactly one result. In the actual macro, a missing key references an undeclared type and conflicting results produce incompatible typedefs. C11 permits repeated typedef declarations of the same non-variably-modified type in one scope, so identical duplicate rows are not necessarily rejected. A project requiring rejection of all duplicates needs a separate schema check. Runtime inference can be explicitly generated from the same facts without turning compile-time lookup into a hidden registry.

## 7. Structural Identity Does Not Depend on Addresses

Let `Atom(id)` denote a named base type and `Apply(k,args)` a constructor application. For finite acyclic trees, this teaching comparison uses stable identifiers and child identities without descriptor addresses:

~~~text
same_type(a, b):
    if a.kind != b.kind: return false
    if a.kind == ATOM: return a.stable_id == b.stable_id
    if a.constructor_id != b.constructor_id: return false
    if a.argument_count != b.argument_count: return false
    for each corresponding pair (x, y):
        if not same_type(x, y): return false
    return true
~~~

Assume collision-free identifiers in the agreed namespace. Induction on height establishes base identity by identifier and constructed identity by constructor and pairwise-equal arguments. Copying or moving a descriptor cannot change those comparisons, so different translation units can express the same type. The model excludes cyclic descriptions and does not infer matching layout, ABI, or cleanup protocols from identity alone; consumers must check those separately.

## 8. Evidence and Summary

Pair each declaration with successful and rejected cases: list bounds, empty arguments, incorrect field types, duplicate traits, unknown generics, and conflicting relation results. Use `cc -E` to inspect prototypes and metadata, cross-translation-unit tests to check identity independently of address, and layout/callback tests to connect descriptors with objects.

CMeta shares finite mapping, punctuation, and tuple extraction. Generics, structures, traits, and type relations retain their own checks. Generation reduces repeated facts; unique matching and structural identity explain when those facts can be shared. Actual owners still govern runtime object lifetimes.
