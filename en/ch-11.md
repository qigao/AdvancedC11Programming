# Chapter 12: Actors: Mailboxes, Serialized Mutation, and Object Lifetime

Multiple producers sending events to one state machine require bounded queueing and protection against simultaneous mutation of the instance. This chapter wraps the existing machine with a mailbox, identity, and generation, then separates sending from draining and execution. The correctness argument covers admission conditions, a single mutating owner, shutdown order, and stale references.

## 1. Identity: Separate Owner from Producer Reference

An Actor owner may look like:

~~~c
typedef struct actor {
    actor_id id;
    uint32_t generation;

    actor_lifecycle lifecycle;

    mailbox inbox;
    machine_instance machine;
    cflow_executor executor;
} actor;
~~~

A producer does not hold an Actor pointer:

~~~c
typedef struct actor_ref {
    actor_id id;
    uint32_t generation;
} actor_ref;
~~~

Therefore **pointer address != actor identity**. After recycle/reload, generation changes and old references become STALE.

## 2. Admission and Single-Owner Drain

~~~text
send(registry, ref, event):

    actor = registry.resolve(ref.id)

    if actor == null:
        return STALE

    if actor.generation != ref.generation:
        return STALE

    if actor.lifecycle != RUNNING:
        return CLOSED

    if actor.inbox.full:
        return FULL

    actor.inbox.push(event)

    schedule_drain_once(actor)

    return OK
~~~

Machine transition does not run in `send()`: **send performs admission; drain performs execution**.

### 2.1 Rejected Send Preserves the Queue

~~~text
send(ref,e) = STALE | CLOSED | FULL
───────────────────────────────────
mailbox_after = mailbox_before
~~~

Do not push first, discover rejection later, and attempt rollback. Admission completes before queue mutation commits.

### 2.2 Drain Algorithm: Multiple Producers, Single State Owner

~~~text
drain(actor):

    require execution_context owns actor mutation

    while actor.lifecycle permits draining:

        event = actor.inbox.try_pop()

        if none:
            break

        result = machine_step(actor.machine, event)

        settle(event, result)

    clear_scheduled_flag(actor)

    if inbox not empty
       and lifecycle permits draining:
        schedule_drain_once(actor)
~~~

Many producers may call send concurrently. But **concurrent `machine_step` count <= 1**. That is the mutable-state isolation Actor provides.

## 3. Lifecycle and Failure

~~~text
CREATED
  start -> RUNNING

RUNNING
  send accepted
  request_stop -> STOPPING
  failure      -> FAILED

STOPPING
  no new send
  settle accepted work
  settled -> STOPPED
  failure -> FAILED

STOPPED
  terminal

FAILED
  terminal
~~~

Critical ordering:

~~~text
request_stop:
    close admission first
    then settle accepted work
~~~

Do not wait for an empty queue before closing admission.

### 3.1 Actor Does Not Own a Thread

Manual Executor, Serial Executor, or a single-thread event loop may all satisfy the same Actor contract. Therefore **Actor semantics != dedicated thread**. Actor requires serialized state mutation. Executor decides how that guarantee is implemented.

### 3.2 Failure and Identity Rules

#### Stale before event validation

For old ref + malformed event, return `STALE` first. An old reference has no authority to invoke the Actor, so payload validation is irrelevant.

#### STOPPING

When `lifecycle = STOPPING`, new `send` calls return `CLOSED`; previously accepted work may still settle.

#### FAILED

FAILED is absorbing by default. Restart/supervision, if desired, belongs to a higher-level policy. The formal model later in the chapter therefore proves lifecycle gating, queue preservation, and refinement to Machine semantics rather than re-proving Machine transitions.

## 4. From Actor Shell to the Canonical Actor

The first eighteen sections give the minimal Actor definition: not “a thread,” but bounded mailbox, non-blocking admission, single mutable owner, explicit lifecycle, and owner/reference/stale-identity boundaries around existing Machine semantics. Multiple Producers increase concurrent admission only; they do not introduce parallel state mutation. The rest of the chapter therefore uses one canonical Actor to examine exactly what this shell adds: only RUNNING accepts send, rejected send preserves the queue, STOPPING closes admission first, FAILED/STOPPED are terminal, and accepted handoff continues to refine the original Machine transition. Then we verify the Lean model, C ownership, identity, and concurrency/lifecycle evidence.

### 4.1 Canonical Actor: Add a Concurrent Shell Around the Same Connection Machine

Chapter 11's Machine already solved Event typing, Transition selection, Guard/Action, Atomic commit, State typing, and Terminal semantics. Actor should not reimplement any of that. Actor adds a different set of questions:

- Who may send?
- When is send allowed?
- Where do messages wait?
- Which execution owner mutates state?
- What happens to old producer refs after owner destruction?
- How does runtime failure enter lifecycle?

Connection Actor should be split into two relations.

**Admission path**: arrows mean message admission/copy into the mailbox.

~~~text
many producer refs
      ↓ send/admission
Actor admission gate
      ↓ accepted event copy
bounded typed mailbox
~~~

**Serialized execution path**: arrows mean execution of an accepted event under a single mutation owner.

~~~text
bounded typed mailbox
      ↓ dequeue
Serial Executor
      ↓ owns mutation context
single Machine Instance
      ↓ execute
Connection Machine SmallStep
~~~

Actor owns one Machine Instance; Serial Executor only guarantees serialized mutation context. This is not the traditional “one Actor, one thread” model. The non-negotiable rule is:

Machine-owned mutable state inside one Actor has only one transition owner at a time. Dedicated OS thread or shared workers are execution policy.

## 5. Semantic Contract: Actor Adds Lifecycle / Admission, Not Transition Meaning

### 5.1 Lifecycle Is New Actor Semantics

Machine has domain terminal state. Actor additionally needs START, RUNNING, STOPPING, STOPPED, and FAILED. Why not reuse Machine state? Because:

| State | Meaning |
|---|---|
| Machine state | application/domain control state |
| Actor lifecycle | runtime ownership/admission state |

A Connection Machine may still be `Connected` while Actor lifecycle is already `STOPPING`. Domain state and runtime admission must coexist independently.

### 5.2 First Phase of Send Is Actor-Gated Admission Only

Producer-ref send should not run Machine transition directly. It only checks:

~~~text
is ref live?
is Actor RUNNING?
is event id/type valid?
is mailbox capacity available?
      ↓
copy into mailbox
      ↓
return exact status
~~~

Send can distinguish `ACCEPTED`, `INVALID_ARGUMENT`, `TYPE_MISMATCH`, `FULL`, `NOT_STARTED`, `STOPPING`, `STOPPED`, `FAILED`, and `STALE`. These are not “error strings.” They are policy inputs for Producers.

### 5.3 Rejected Send Must Preserve the Queue

If send returns:

~~~text
FULL
STOPPING
STOPPED
FAILED
STALE
TYPE_MISMATCH
~~~

the primitive must not partially write, overwrite an old message, silently drop another message, retry automatically, or change Machine state. The key contract is:

~~~text
mailbox after
=
mailbox before
~~~

This mirrors rejected-task ownership in Executor.

### 5.4 Multiple Producers Do Not Change FIFO / Single-Consumer Semantics

Multiple Producers mean only that many threads may attempt admission; they do not mean that many threads may execute transitions concurrently. Mailbox commit may support MPMC admission; Machine execution remains **one consumer + one serialized transition stream**. The problem changes from “lock the whole domain object” to concurrent enqueue + serialized mutation.

### 5.5 Actor Owner and Producer Ref Must Be Separate

If producer holds Actor owner pointer directly, owner destruction creates:

```text
old producer still calls send
    ↓
use-after-free
```

So separate:

| Object | Ownership |
|---|---|
| Actor owner | owns root reference and lifecycle control |
| Actor ref | independently retained producer capability |

Destroying owner need not immediately free the small control block. The runtime can:

```text
mark refs stale
close runtime
release root
wait until last producer ref released
    ↓
reclaim control block
```

STALE becomes a semantic status rather than wild-pointer behavior.

### 5.6 Stale Classification Should Precede Event Validation

If a stale producer ref sends an unknown event id or wrong payload type, the most important fact is still **this reference no longer targets a live Actor**. STALE should therefore classify before schema errors. The caller should not keep inferring schema/lifecycle state from an invalid runtime capability.

### 5.7 STOPPING Must Close Admission First

The first effect of `request_stop` should be **no new messages admitted**. Only then should it cancel/close queued runtime, settle in-flight work, and transition to `STOPPED`. Otherwise Producers can keep adding messages during shutdown and there is no finite settlement boundary.

### 5.8 FAILED Is Terminal Lifecycle, Not Implicit Restart

If Machine/Subscription/runtime fails:

```text
Actor -> FAILED
```

later send returns `FAILED` rather than silently creating a new Machine Instance, retrying the message, or restarting with old/new state. Automatic restart belongs to Supervisor/Application policy, not Actor primitive.

## 6. Lean: Actor Adds Only Lifecycle Gate and Reuses Machine Semantics

The edition formal calculus contains `CMetaCFlowCalculus/CFlow/Actor.lean` and `CMetaCFlowCalculus/Proofs/Actor.lean`. Its state follows this chapter closely:

~~~text
Actor.State
    lifecycle
    mailbox
    live
~~~

Importantly:

> Actor formal state does not copy Machine transition state.

That emphasizes: **Machine/Mailbox remain authoritative; Actor only adds a lifecycle admission boundary.**

### 6.1 `State.Valid`: Lifecycle and Mailbox Terminal Must Agree

Formal `Actor.Valid` requires:

~~~text
mailbox.Valid
+
mailbox.terminal
=
lifecycle.expectedMailboxTerminal
~~~

where:

~~~text
START/RUNNING
    → mailbox OPEN

STOPPING/STOPPED/FAILED
    → mailbox CANCELLED
~~~

Lifecycle is therefore not a flag unrelated to Mailbox. It constrains the admission substrate directly.

### 6.2 Start / RequestStop / Settle / Fail Preserve Validity

Existing theorems include `start_preserves_valid`, `requestStop_preserves_valid`, `settle_preserves_valid`, and `fail_preserves_valid`; together they show that lifecycle transitions cannot create contradictory combinations such as:

~~~text
Actor STOPPED
+
Mailbox OPEN
~~~

### 6.3 `requestStop_cancels_pending`

For START/RUNNING:

~~~text
requestStop
    ↓
mailbox queue = []
mailbox terminal = CANCELLED
~~~

This precisely models shutdown admission boundary. Actor stop is more than setting `state = STOPPING`; it must terminate the message entrance too.

### 6.4 `send_accepted_only_running`

The theorem `send_accepted_only_running` proves that if send returns ACCEPTED, the previous state must satisfy:

~~~text
live = true
lifecycle = RUNNING
~~~

That gives Producer API a strong semantic statement.

### 6.5 `send_accepted_appends_once`

The theorem `send_accepted_appends_once` proves:

~~~text
queue_after
=
queue_before ++ [event]
~~~

for accepted send. That expresses no overwrite, no duplicate insertion, and no hidden reordering at the abstract admission layer.

### 6.6 `send_rejected_preserves_queue`

Correspondingly, `send_rejected_preserves_queue` proves every non-ACCEPTED result satisfies:

~~~text
queue_after
=
queue_before
~~~

This is the core correctness property of bounded non-blocking admission.

### 6.7 STOPPED / FAILED Are Absorbing

Theorems include `stopped_cannot_restart`, `failed_cannot_restart`, `stopped_is_terminal`, and `failed_is_terminal`. Actor primitive has no implicit resurrection. Restart means:

> create a new Actor or use a higher-level Supervisor protocol.

### 6.8 `accepted_handoff_refines_machine`: Actor Does Not Invent a New Transition

The most important theorem is `accepted_handoff_refines_machine`. It defines Actor handoff as a **refinement mapping**, not a second transition system:

~~~text
Actor send accepted
      ↓ same Event admitted
Mailbox receives exact same Event
      ↓ hand off to existing semantics
existing Machine RuntimeStep
~~~

and proves:

~~~text
Actor was live/running
event appended once
same event received
Machine after.trace
=
before.trace ++ Machine traceSuffix
~~~

This theorem makes the architecture very clear:

Actor is only an admission/lifecycle shell; real domain state transition remains the Machine semantics from Chapter 11. There is no Actor-specific “second commit state.” That is a strong validation of composition.

## 7. Current C Implementation and Runtime Identity

Current CFlow Actor API explicitly separates:

| Handle | Ownership |
|---|---|
| cflow_actor | owner handle |
| cflow_actor_ref | independently retained producer handle |

Both are opaque handles, but with different ownership.

The earlier `actor_ref { id, generation }` shape is a **semantic teaching model**, not the public ABI layout. The pinned snapshot actually publishes two zero-initialized opaque handles:

~~~c
typedef struct cflow_actor {
    void *impl;
} cflow_actor;

typedef struct cflow_actor_ref {
    void *impl;
} cflow_actor_ref;
~~~

Generation/invalidation is represented by the retained internal control block. Callers must not inspect `impl` to infer whether an Actor is live. Producers retain capability through the acquire/retain/release protocol:

~~~c
cflow_actor_ref producer = {0};
cflow_actor_ref second_producer = {0};

if (!cflow_actor_ref_acquire(&actor, &producer))
    return false;

if (!cflow_actor_ref_retain(&producer, &second_producer)) {
    cflow_actor_ref_release(&producer);
    return false;
}

/* Publish each ref to its producer with application synchronization. */

/* When producer use ends, release each independently retained ref once. */
cflow_actor_ref_release(&second_producer);
cflow_actor_ref_release(&producer);
~~~

Plain C assignment:

~~~c
second_producer = producer;
~~~

is **not retention**. Releasing both variables afterward would treat one ownership token as two. Capability duplication must go through `cflow_actor_ref_retain`.

Owner destruction is deliberately independent of producer-reference lifetime. Assuming `event` is a valid `cflow_event_view` constructed according to this chapter's contract:

~~~c
cflow_actor_ref producer = {0};

if (!cflow_actor_ref_acquire(&actor, &producer))
    return false;

/* Owner-side serialization: destroy closes the runtime and stales refs. */
cflow_actor_destroy(&actor);

cflow_actor_send_status status =
    cflow_actor_ref_try_send(&producer, &event);

if (status != CFLOW_ACTOR_SEND_STALE) {
    cflow_actor_ref_release(&producer);
    return false;
}

cflow_actor_ref_release(&producer);
~~~

There is no use-after-free here. `cflow_actor_destroy` marks the control block stale, closes the runtime, clears the owner handle, and releases the root reference; the control block is reclaimed only after the final producer ref is released. In the pinned implementation, `cflow_actor_ref_try_send` checks stale under the same gate before event/lifecycle validation, so a revoked capability deterministically reports `CFLOW_ACTOR_SEND_STALE` rather than regaining authority through address reuse.

### 7.1 Actor Owns the Runtime Shell

Actor ownership can be summarized as:

| Owns | Borrows |
|---|---|
| Machine or Statechart Instance | immutable definition |
| bounded Mailbox | SerialExecutor |
| identity Graph | concurrent Scheduler |
| Subscription | guard/action bindings |
| lifecycle control block | callback contexts |
| root reference | type descriptors |

This lets destruction order be specified precisely.

### 7.2 Scheduler Requires CONCURRENT Capability

Why is Actor's outer Scheduler concurrent while Machine transition remains Serial? They solve different problems:

| Capability | Responsibility |
|---|---|
| Scheduler | many Actors / async wakeups share execution resources |
| Machine SerialExecutor | one Actor's state mutation remains serialized |

So **concurrency outside, serialization inside** is not a contradiction. It is the core of Actor scalability.

### 7.3 Actor Send Explicitly Forbids Hidden Behavior

Current Producer send contract promises **never blocks / never retries / never overwrites / never resizes / never silently drops / never allocates**. This is a strong bounded-runtime promise. FULL really means FULL. If the application wants retry later, drop newest, drop oldest, fail request, or apply upstream backpressure, it decides explicitly.

### 7.4 Owner Destroy Marks Refs Stale Before Reclaiming Root

Destroy contract is an **ownership/lifecycle sequence**:

~~~text
mark producer refs stale
      ↓ close live runtime
synchronously close selected instance/Subscription
      ↓ detach owner
clear owner handle
      ↓ release root ownership
release root reference
      ↓ wait for retained producer refs
last producer ref releases
      ↓ reclaim
control block reclaimed
~~~

Producer can safely observe STALE instead of touching a freed owner object.

### 7.5 Identity: Why Actor Cannot Rely on Pointer Address

Actor identity has at least two layers.

#### 7.5.1 Runtime Object Identity

A Producer Ref must know whether it still targets the same live Actor generation/control block. After owner destroy, a pointer-shaped capability must not continue to represent a valid identity. STALE is the combined result of identity and lifetime.

#### 7.5.2 Domain Identity

Higher-level systems may also need domain keys such as user actor, device actor, connection actor, and order actor. These should not equal runtime address. Actor runtime may be replaced/rebuilt; whether domain identity continues is Supervisor/Application policy. So the book keeps the same principle:

address is representation location, not semantic identity. This is the same thread as Type descriptor, Callable identity, and Graph certificate identity.

## 8. Evidence: Actor Must Validate Concurrent Admission + Serialized Mutation + Lifecycle

### 8.1 Bounded Multi-Producer Admission

Concurrent Producers sending simultaneously must satisfy:

- accepted count <= capacity available;
- FULL does not alter queue;
- accepted events each appear exactly once;
- no silent drop.

Queue order should follow the documented mailbox commit/FIFO contract, not assumed producer call-start order.

### 8.2 Single Mutable Owner

Machine transition instrumentation should validate **in-flight transition count <= 1** even under many producers, a concurrent scheduler, and a shared worker pool. This proves Actor semantic isolation more directly than “it did not crash.”

### 8.3 Lifecycle Admission Matrix

Test:

~~~text
START
    send → NOT_STARTED

RUNNING
    send → ACCEPTED/FULL/type error

STOPPING
    send → STOPPING

STOPPED
    send → STOPPED

FAILED
    send → FAILED

owner destroyed + retained ref
    send → STALE
~~~

### 8.4 Ref Lifetime / Stale Stress

Ref lifetime / stale stress should cover, in order:

1. acquire many refs;
2. concurrent send;
3. owner destroy;
4. refs observe STALE;
5. release refs in arbitrary order;
6. last ref frees control block.

Run this under sanitizer/stress gates. This is one of the easiest areas for Actor C implementation to produce use-after-free.

### 8.5 Actor-to-Machine Refinement Evidence

Use the Connection Machine from the previous chapter and send Connect, ConnectedEvent, Disconnect, and ClosedEvent through both a direct Machine Instance and the Actor mailbox/ref path. Compare Machine state, observation trace, consumed event count, and first error; they should agree. This is the C-side differential counterpart of `accepted_handoff_refines_machine`.

### 8.6 Failure Evidence

Force Machine action failure, Subscription failure, and Scheduler admission failure; verify that Actor enters FAILED once, rejects later sends, retains the first failure, does not implicitly restart, and settles ownership.

## 9. CNet 2.3 SG + ACE Strategy: When an Actor Shell Is Unnecessary

This is a **separate later released-SDK comparison**, not a rewrite of the chapter's pinned Actor implementation. Its source evidence is Salts `v2.3.0-rc.4` in `cnet/owner_placement.h`, `destination_policy.h`, `handoff.h`, `manager.h`, and `client_pool.h`; an executable installed-consumer check lives in [`qualification/ch12_cnet_strategy.c`](../qualification/ch12_cnet_strategy.c). CI continues to consume the newest published SDK rather than pinning that source tag.

The Actor described above solves **application-level message admission, mailbox ownership, and serialized state mutation**. When CNet Sharded Graph (SG) already owns network I/O progression and connections, introducing an additional Actor may duplicate queues, lifetimes, and execution hops rather than improve throughput. Start with ordinary C and the existing CNet Owner:

~~~text
listener accepts detached TCP stream
  -> server cnet_owner_placement_choose()       # advisory decision only
  -> cnet_handoff_reserve/publish()              # bounded credit; moves stream
  -> final Owner: take -> cnet_manager_adopt()   # CNet owns transport progression
  -> Owner drives CNet and manager.advance()
  -> terminal + context/lease settlement        # then return handoff credit
~~~

This is **illustrative pseudocode** for a multi-Owner host, not a claim that every call happens on the same thread. A successful `choose()` is not reserved capacity; successful `publish()` transfers the detached stream, which the producer must neither re-publish nor close. Destroying the handoff inbox also requires real producer/wake-tail quiescence. Established connections are not moved by re-evaluating placement.

The Strategy dimensions are distinct:

| Boundary | Selection domain | Required invariant |
|---|---|---|
| Server Owner Placement | Final local SG Owner | `STRICT_KEY` uses `key_hash % owner_count`; a full pinned Owner is rejected, not silently replaced |
| Client Destination Policy | Remote Endpoint set | `STRICT_KEY` uses rendezvous hashing of stable `endpoint_id` values, **not array indices**; an ineligible winner rejects without rerouting |
| Client Pool | Protocol-READY physical connections on the same Owner | Actual protocol-slot leases must be reserved; no hidden dial, thread, wait, or reconnect |
| Recovery / Retry | Transport restoration and **logical application request retry** | `CONNECTED != protocol READY`; recovering TCP never by itself permits DATA replay |

Client admission is also **choose, then actually admit**:

~~~text
remote_candidate = destination.choose(eligible_snapshot)
if candidate rejected: report the error; do not silently choose another
connection = owner_local_pool.try_acquire(compatible_key, protocol_slot)
if no READY lease: caller explicitly decides whether/when to dial
logical_request_retry = retry.evaluate(application + protocol evidence)
~~~

A CMeta `CMETA_INTERFACE` can provide an ACE-style **typed Strategy/Observer callback** and deliver the choice to an ordinary C function. It does not thereby instantiate another Reactor, Proactor, or transport owner. Reach for this chapter's Actor layer only when the application genuinely needs an independent mailbox, producer identity, typed events, and its own serialized domain state.

The directly checkable boundaries are `policy selection != capacity reservation`, `transport connected != protocol ready`, and `reconnect != application retry`. These are API admission contracts, not automatic correctness conclusions from the term SG.

### 9.1 Two Real SG Owners: TCP Handoff and Reclamation

The earlier `ch12_cnet_strategy.c` verifies pure selection/admission results without opening a socket. The separate strict-C11 installed consumer [`qualification/ch12_cnet_sg_handoff.c`](../qualification/ch12_cnet_sg_handoff.c) runs **two actual NativeIO SG shards**, each with its own host lease and external CNet client. The accepted TCP stream is genuine loopback I/O, not a fabricated socket.

~~~text
Owner 0                               Owner 1
listener.accept_detached()
  |                                      |
placement.choose(1)                     |
handoff.reserve()  -- bounded credit -->|
handoff.publish(socket) ---------------> handoff.take()
                                         manager.reserve()
                                         manager.adopt(socket)
CNet sends "ping" ---------------------> CNet receives "ping"
CNet receives "pong" <------------------ CNet sends "pong"
CNet terminal                           CNet terminal
listener/client cleanup                 manager.advance() -> recycle
                                         handoff.release(ticket)
         final SG barrier  ->  inbox seal/destroy  ->  SG shutdown
~~~

Each Owner progression turn calls `native_io_sharded_context_observe_host()` once and dispatches its NativeIO completions with `cnet_sg_host_route_batch()`. Callbacks verify thread-Owner affinity. A successful `publish` relinquishes the producer's detached socket; only the final Owner returns the handoff credit after `take`, `adopt`, real application receive, terminal notification, and Manager recycling. A duplicate `release` must fail. The host authorizes closing only after **both** peers have completed send and receive: send completion alone is not remote application delivery.

This test establishes **one actual TCP execution path** against the newest published installed SDK, not multi-producer stress, mobile execution or a throughput benchmark. Each CNet SG Owner remains the sole authority for its backend, connection and callbacks; an additional Actor mailbox is unnecessary.

## 10. CMeta + CFlow ACE Active Object: Add an Application Mailbox Only When Needed

This section uses **later released Salts 2.3 CFlow/ACE interfaces**. The independent installed C11 program [ch12_cmeta_ace_active_object.c](../qualification/ch12_cmeta_ace_active_object.c) tests a **different engineering path** from the preceding live CNet SG TCP handoff. Active Object is for an application-owned typed event/state machine, not another wrapper around an SG transport.

### 10.1 One Typed Declaration, Two Explicit Owners

The application declares `book_ace_actor_port.send(int)` and `book_ace_actor_work.transform(int)` with `CMETA_INTERFACE` and supplies ordinary C implementations via `CMETA_IMPLEMENTS`:

~~~text
application Producer
  -> typed CMeta Port.send(value)
  -> cflow_actor_ref_try_send(typed event)      # admission, not execution
  -> CFlow Actor mailbox (capacity = 2)
  -> CFlow Machine action
  -> typed CMeta Strategy.transform(value)
  -> Subscriber receives one result
~~~

The CMeta Port/Strategy values are borrowed `{self,vtable}` capabilities plus FunctionDesc/FunctionAbi. **CFlow Actor**, not CMeta, owns the mailbox, Machine Instance, and stop/cancellation state. **CFlow Scheduler/Executor** owns worker execution capability. One admitted payload `7` yields one delivered result `107` and one Strategy invocation in the executable gate; this is not a general Actor performance claim.

### 10.2 STOPPED, STALE, and Borrow Lifetimes

~~~text
RUNNING: try_send(7) -> ACCEPTED -> one delivery(107)
request_stop -> wait -> STOPPED
STOPPED: try_send(8) -> STOPPED
actor_destroy, retained producer ref
STALE:   try_send(9) -> STALE
producer_ref_release -> end ref authority
~~~

The Port **borrows a Producer Ref** rather than owning the Actor. The caller keeps that ref until testing STALE and then releases it. Every Strategy context must remain valid until the Actor can no longer invoke it. CFlow Machine enforces serialized mutation under its actual runtime contract; no such property follows from the presence of CMeta Interface metadata.

### 10.3 Half-Sync/Half-Async, Pipes and Filters, and CNet Composition

Client/server network I/O remains in `CNet/NativeIO`. When CPU work must move off the I/O Owner, an explicit bounded `CFlow Channel` carries a copied value; downstream demand chooses a `Filter -> Map` Graph, Scheduler, or an application Actor. `FULL` must be addressed by the protocol through rejection, backpressure, or explicit loss policy; Channels do not silently become unbounded. Choose Actor only if the application owns typed events, lifecycle, and mutable domain state. Use the prior SG handoff for moving a TCP socket to a final network Owner.

An ACE pattern is not a framework that must be installed as a set. It decomposes replaceable behavior, execution policy, and lifetime duties into checkable contracts. For concurrent networking, `Acceptor-Connector/Proactor + CNet SG` and a `CMeta typed Strategy` may already be sufficient; choose `CFlow Active Object` only if separate application semantics justify it.

## 11. Reactor and Proactor: Two ACE Event Models, Different Ownership Boundaries

ACE **Reactor** structures “wait for readiness → dispatch an event to a Handler”; **Proactor** structures “submit an asynchronous operation → observe its completion → handle the result.” Both require bounded admission, explicit callback lifetimes, and correct failure/shutdown progression. Merely using epoll/kqueue does not prove a pure Reactor implementation, and a completion token is not itself a Proactor engine.

Salts 2.3 assigns real I/O authority to NativeIO/CNet; CMeta contributes typed Handler/Strategy facts. Here are **two executable installed-C11 paths**, rather than two competing event loops:

| | Reactor-style application dispatch | Proactor NativeIO/SG completion path |
|---|---|---|
| Start | External Acceptor checks readiness via `cnet_listener_wait` | NativeIO/CNet asynchronous request already submitted |
| Progress | One caller invokes `cnet_client_poll`, dispatching to a borrowed typed CMeta Handler | Final SG Owner calls `native_io_sharded_context_observe_host` and routes completions through `cnet_sg_host_route_batch` |
| Lifetime | Listener close stops new accepts, not established connections | Detached socket transfers through handoff credits, returned only after terminal + Manager recycle |
| Typed application facts | CMeta `CMETA_INTERFACE` with exact `FV1` state method | CMeta FunctionAbi describes observers; NativeIO completion token settles once |
| Execution authority | CNet owns actual NativeIO observation; no additional kernel Reactor | SG shard host lease owns observation; no second Client poll |
| Executable source | [`ch12_ace_reactor_dispatch.c`](../qualification/ch12_ace_reactor_dispatch.c) | [`ch12_cnet_sg_handoff.c`](../qualification/ch12_cnet_sg_handoff.c), plus the one-shot token in [`ch03_cmeta_ace_patterns.c`](../qualification/ch03_cmeta_ace_patterns.c) |

### 11.1 Reactor-style: Readiness Does Not Transfer Connection Ownership

~~~text
listener.wait() -> ready
  -> listener.accept(owner, typed_observer)
  -> owner.poll() -> on_state(...) -> CMeta Interface.observe(state)
  -> application decision -> close connection
  -> owner.poll() -> terminal callback
  -> stop/destroy CNet Owner
  -> release borrowed Handler context
~~~

The new consumer uses real loopback TCP. `CMETA_INTERFACE` generates a fully reflected exact `observe(int)`, and `CMETA_IMPLEMENTS` binds it to ordinary C counters. An invalid connection configuration is rejected before producing a handle or callback. Each successful connection yields one `CONNECTED` and one terminal event, with explicit checks for wrong-Owner or post-provider-lifetime callbacks.

**Semantic limit:** `cnet_client_poll()` internally uses CNet coroutines observing NativeIO **completions**. This is therefore a *Reactor-style application readiness/dispatch structure*, **not** a separately implemented pure kernel Reactor.

### 11.2 Proactor: Completion Authority and the Final Socket Owner

~~~text
Owner 0 listener accepts detached TCP
    -> choose owner -> handoff.reserve/publish
Owner 1 native_io_sharded_context_observe_host()   # sole observe authority
    -> cnet_sg_host_route_batch()
    -> handoff.take -> manager.reserve/adopt
    -> receive/send completion -> CNet callbacks -> terminal
    -> manager.advance()/recycle -> handoff.release once
SG round barrier -> inbox seal/destroy -> SG shutdown
~~~

`ch12_cnet_sg_handoff.c` runs **two independent SG Owners** and exchanges genuine `ping/pong` on the final Owner. It checks callback affinity, rejection of duplicate credit release, and the shutdown order after terminal and recycle. Chapter 10 separately validates `NATIVE_IO_ACE_TOKEN_TYPE` as a one-attempt request/endpoint/user-data completion identity; that token **does not submit, poll, or own a socket**.

### 11.3 Selecting the Right Model

For high-connection-count admission with one I/O Owner, prefer the already supplied CNet SG and its policies. A readiness-driven application may use the Reactor-style typed Handler. A completion-driven pipeline should use the existing NativeIO/CNet Proactor owner protocol. Add CFlow Active Object only when a separate application mailbox and domain state are justified. Across all these models, preserve `choose != reserve`, `send completion != remote application receive`, and `connection terminal != manager/context recycle`. Performance comparisons require their own equal-platform, equal-workload benchmark evidence.

## 12. Summary

Actors separate concurrent admission from serialized execution: producers submit typed events, a mailbox bounds pending work, and one executor mutates the machine instance. Identity and generation reject stale references so address reuse cannot restore their authority. Shutdown first closes admission, then settles accepted events through execution or cancellation and cleanup. Queue correctness, machine-transition semantics, and Actor lifetime have distinct proof obligations whose contracts must remain compatible when composed.
