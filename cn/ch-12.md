# 第十三章：CMeta 工程边界：类型身份、ABI 与动态库

头文件中的静态描述符进入不同翻译单元或动态库后，可能有多份表示。代码也可能在调用者仍保存函数指针时被卸载。CMeta 的类型身份、Plugin 租约与 ABI 检查因此必须经过真实编译、链接和加载验证。本章把这些边界落实为一个多文件例子和一条完整的卸载顺序。

## 1. 让两个翻译单元产生独立描述符

翻译单元（translation unit，TU）是一个源文件经过预处理后交给编译器的输入。头文件中的 `static` 对象具有内部链接；两个源文件各自包含它，就各自得到表示对象。下面的 `user_meta.h` 用一个单字段类型隔离身份问题，不是第八章服务响应的完整 `User` 布局。

~~~c
#ifndef BOOK_USER_META_H
#define BOOK_USER_META_H

#include <cmeta/cmeta.h>

typedef struct BookUserId {
    int id;
} BookUserId;

static const cmeta_type_identity BookUserId_identity =
    CMETA_TYPE_ID_ATOM_INIT("book.UserId.v1");

static const cmeta_type_desc BookUserId_desc = {
    .name = "BookUserId",
    .size = sizeof(BookUserId),
    .align = _Alignof(BookUserId),
    .kind = CMETA_T_OBJECT,
    .pointee = NULL,
    .traits = NULL,
    .identity = &BookUserId_identity
};

static inline const cmeta_type_desc *book_user_type(void)
{
    return &BookUserId_desc;
}
#endif
~~~

`tu_a.c` 与 `tu_b.c` 分别提供自己的描述：

~~~c
/* tu_a.c */
#include "user_meta.h"

const cmeta_type_desc *type_from_a(void)
{
    return book_user_type();
}
~~~

~~~c
/* tu_b.c */
#include "user_meta.h"

const cmeta_type_desc *type_from_b(void)
{
    return book_user_type();
}
~~~

`main.c` 比较语义，返回零表示通过。这里不把“地址必须不同”设为公共接口的要求；测试的目标是即使表示独立，语义比较仍然正确。

~~~c
#include <cmeta/cmeta.h>

const cmeta_type_desc *type_from_a(void);
const cmeta_type_desc *type_from_b(void);

int main(void)
{
    const cmeta_type_desc *a = type_from_a();
    const cmeta_type_desc *b = type_from_b();
    return cmeta_type_equal(a, b) &&
           cmeta_type_identity_equal(cmeta_type_identity_of(a),
                                     cmeta_type_identity_of(b))
           ? 0 : 1;
}
~~~

`traits = NULL` 在此表示未声明附加能力，不能把这个描述直接用于要求复制、销毁或比较特征的算法。身份与算法所需能力是两项检查。

## 2. 相等规则必须符合被比较的对象

第二章的类型身份用原子标识、指针、限定和泛型应用构成结构。对泛型应用比较构造器和参数；按有限树递归，只要对应叶子身份相同、构造关系相同，就得到结构身份相同。描述符的大小、对齐、种类等契约仍由相应类型检查负责，稳定字符串不能赦免不一致布局。

| 比较对象 | 应使用的事实 |
|---|---|
| TypeDesc | `cmeta_type_equal` 的语义类型检查 |
| 类型身份 | `cmeta_type_identity_equal` 的结构比较 |
| FunctionDesc | 名称、参数、结果、标志与行为契约 |
| FunctionAbi | 本地承载类别与相应函数契约 |
| Callable | 权威执行表示以及相关捕获 |
| DataBind 操作 | 限定契约身份、版本、操作与请求响应关系 |

同一个原函数在两个 TU 中可能有不同的生成包装地址。规范原始调用目标是身份依据时，不应仅因包装地址不同就判为不同调用；适配表示则需要检查其规定的适配入口与捕获。`bind(multiply, 10)` 和 `bind(multiply, 20)` 即使代码入口相同也不是同一个可调用值。

FunctionDesc 相等不证明两段机器码实现相同，也不能代替 FunctionAbi 检查。这一边界影响优化器重复节点判断、AOT 匹配和 Plugin 准入，不能用一条统一的指针比较代替。

## 3. 通过安装包编译多文件例子

把上节四个文件放在独立目录，使用以下 `CMakeLists.txt`：

~~~cmake
cmake_minimum_required(VERSION 3.20)
project(book_identity C)

find_package(Salts CONFIG REQUIRED)

add_executable(book_identity main.c tu_a.c tu_b.c)
target_compile_features(book_identity PRIVATE c_std_11)
target_link_libraries(book_identity PRIVATE Salts::CMeta)
~~~

先把固定快照的 SDK 安装到独立前缀，再让这个项目只通过安装包配置查找它。构建例子的目的，是让公开头文件、编译配置和链接目标同时参与验证；不能额外加入源码树私有 include 来“修好”安装缺失。

Salts 是真实包名与 CMake 命名空间；正文组件名仍是 CMeta、CFlow 和 CMeta Plugin。`Salts::CMeta`、`Salts::CFlow`、`Salts::Plugin` 必须按实际导出名称书写。

## 4. 动态库的代码也有生存期

DSO 是 dynamic shared object（动态共享对象），例如 ELF 共享库；Windows 上的 DLL 承担相应角色。主机持有的描述符、类型特征函数、thunk 和 vtable 都可能指向动态库。只保证数据对象仍在堆上，并不能保证调用目标仍已加载。

`cmeta_plugin_registry_acquire` 从已启动的模块取得 lease（租约），覆盖借用的 manifest、导出、描述符与代码。它是生存期凭据，不是到时自动过期的网络租约。先通过 `cmeta_plugin_registry_load` 加载，再通过 `cmeta_plugin_registry_start` 启动。下面是包含 `<salts/plugin.h>`、已取得有效 registry 与启动后 ref 的调用片段：

~~~c
cmeta_plugin_lease lease = {0};
const cmeta_plugin_manifest *manifest = NULL;
cmeta_plugin_status status = cmeta_plugin_registry_acquire(
    &registry, ref, &lease, &manifest);
if (status != CMETA_PLUGIN_OK)
    return status;

/* Use manifest and exports while lease remains live. */
~~~

取得成功后，外层所有者按下一节的顺序完成使用与清理，再释放租约。取得失败不能使用 `manifest`；错误路径只清理已经成功取得的资源，并保留诊断。片段没有展示 registry 的建立与关闭，它们由外层模块控制代码负责。

## 5. 从生存期推出卸载顺序

假设某次调用仍可能执行 Plugin 提供的 `destroy`。若先释放最后租约并卸载模块，再销毁返回对象，即使业务函数早已返回，也会跳到失效代码。正确区间必须覆盖绑定、调用、输出和最终清理。

~~~text
retire_plugin:
    prevent the application from starting new uses
    request plugin stop, closing new lease admission
    finish accepted calls and callbacks under their live leases
    destroy dependent native values, adapters, and plans
    release each acquired lease and check the release result
    establish plugin quiescence through its lifecycle protocol
    unload only after no leases or lifecycle callbacks remain
~~~

**静止（quiescence）**表示相关使用与回调已结束，不会再访问资源。活动租约阻止卸载；没有租约也不足以跳过生命周期检查。固定快照要求允许卸载的生命周期状态，并且没有活动租约或生命周期回调。

租约释放成功会消费并清零租约；非成功返回保持其值不变。调用方不能无论返回值如何都把它当作已经释放。旧模块引用的 generation（代号）用于识别回收后的身份，但读取这些信息仍须通过有效 registry 和正式句柄，不允许解引用卸载后的 manifest。

## 6. 精确 ABI 代际

ABI 是 application binary interface（应用二进制接口），覆盖调用方式、布局、符号和跨模块约定。ABI epoch 是一组二进制契约的代际标识。本版 CMeta Plugin 要求精确当前 epoch 和精确当前 manifest/export 布局，不协商旧版本。

~~~text
admit_manifest(manifest):
    require struct_size equals the current layout size
    require abi_version equals CMETA_PLUGIN_ABI_VERSION
    validate every exposed export and its contract
    reject before consuming incompatible descriptor pointers
~~~

`struct_size` 的存在不等于支持“可读前缀兼容”。某些独立提供方接口可以明确采用最小前缀加可选尾字段的规则，但 Plugin 的精确代际规则不能从这种设计类推。相同 epoch 也不替代类型、所有权和导出契约检查。

真实运行接口与代际说明位于 [plugin/include/salts/plugin.h](https://github.com/qigao/salts/blob/a650262031e9b3e5f11a227a7911a75db9ae1fb8/plugin/include/salts/plugin.h)。路径保留发行包名称，公共符号采用 `cmeta_plugin_*`。

## 7. 公共可见字段与配置

| 字段类别 | 使用方可以做什么 |
|---|---|
| 配置行和公开结果字段 | 按文档初始化或读取 |
| Graph/Plan 的只读检查字段 | 用于诊断与验证，修改仍走公开 API |
| 不透明句柄的 `impl` | 零初始化及交给 API；不解引用、不序列化、不复制活动所有者 |

编译期配置也可能进入 ABI。CMeta 已知类型集合与可调用签名集合并不完全相同；修改影响签名的配置时，所有相关 TU 必须看到一致设置。CFlow 导出的 Machine 限制也应通过安装目标传递给使用方。无法被工具链自动诊断的不一致仍是不支持状态，不能期待运行时猜测修复。

`_Generic`、静态类型断言和宏生成需要调用点的 C 类型信息，适合放在公开头文件；图验证、身份比较、运行时队列和计划编译可以放在编译库中。按信息所在位置划分实现，既保留类型检查，也避免把全部运行时代码复制到每个 TU。

## 8. 生成产物与工具链检查

形式模型导出的签名表和策略表应由原始模型与生成器产生，验证时运行对应的检查模式，避免手工编辑生成头文件。普通 C 使用方构建可以消费已提交产物，不必运行 Lean；发布方仍须证明产物没有漂移。

编译器扩展也属于公开前提。需要原生类型查询、cleanup 属性或特定段布局时，应按第一章的能力入口检查。缺少能力时明确拒绝或选择另有说明的接口，不能偷偷强转后声称原类型保证仍成立。

| 主张 | 对应验证 |
|---|---|
| 类型身份跨 TU | 本章独立表示例子及不匹配反例 |
| 契约跨动态库 | 真实主机与共享库，检查 epoch 和布局拒绝 |
| 借用阻止错误卸载 | 活动租约下 BUSY，清理和静止后卸载 |
| 安装包完整 | 新目录仅使用已安装头文件和导出目标 |
| 内存与回调生存期 | 失败路径、并发时序及 sanitizer |
| 生成事实一致 | 生成器检查和对应形式工程验证 |

单独比较 `sizeof` 无法覆盖调用约定、符号、枚举语义、所有权或关闭行为。把 FULL 改为静默丢弃，即使结构布局未变，也改变了调用方依赖的行为契约。来源快照和组合构建限制继续以 `SOURCE_SNAPSHOTS.md` 为准。

## 9. 小结

语义身份允许独立描述符表示同一契约，实际 ABI 检查仍约束布局、承载类别和配置。Plugin 租约覆盖代码、数据及清理，卸载还要求生命周期静止。独立翻译单元、真实动态库和安装后使用方分别验证不同边界；源码树内的一次成功链接不能替代这些证据。
