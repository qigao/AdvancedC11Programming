# 第二章：有限元编程：泛型、结构体、特征与类型关系

字段和参数常被重复用于本地声明、类型检查和反射。CMeta 的有限元编程内核负责统一拆解这些行，各个使用方再解释自己的语义。本章沿用 `id`、`score` 字段，展示字段投影、泛型、特征和类型关系怎样共享机械展开，而不共享一套模糊的运行时类型系统。

**元组（tuple）**是在固定位置保存元素的一行记号，例如 `(int, id, flags)`；它不是运行时容器。**投影（projection）**从这一行取得类型、名字或其他部分。相同位置必须在所有使用方中有相同含义，否则“复用宏”仍会生成互不一致的声明。

## 1. 有限映射与分隔策略

下面是固定入口的调用形状，省略号代表尚未展开的参数：

~~~c
CMETA_PP_MAP(M, C, a, b, c)
CMETA_PP_MAP_N(3, M, C, a, b, c)

CMETA_PP_MAP_COMMA_N(...)
CMETA_PP_MAP_SEMI_N(...)
CMETA_PP_MAP_PREFIX_COMMA_N(...)
~~~

本版的列表映射按明确的 0–16 项边界展开。显式元数入口把计数交给调用方；由参数自动计数的入口还有自己的空参数和工具链条件。超出支持范围不是“多做几次循环”，而是不受支持的声明，必须在约定边界拒绝。

考虑参数行 `(int, fd)` 与 `(size_t *, written)`。生成原型时要在两行之间放一个逗号；生成字段时要在每行后放分号；生成调用实参时只取名字。下面的伪代码把分隔规则与行内容分开：

~~~text
project(rows, emit, separator):
    reject a row count outside the supported bound
    for i from 0 to row_count - 1:
        if i != 0: emit separator
        emit the projection of rows[i]
~~~

**展开推导。** 处理前 `i` 行后，结果中恰有 `i` 个投影和 `max(i - 1, 0)` 个分隔符。下一行先在非首行位置追加一个分隔符，再追加一个投影，不变量继续成立。因此空列表不产生分隔符，非空列表不会多出尾逗号。实际预处理器用有限宏族实现这一过程，伪代码中的循环只用于解释展开结果。

## 2. 记号关系、本地类型与语义身份

预处理器可以识别已登记的记号，却不解析所有 C 类型。例如 `typedef void nothing;` 不要求一个检测字面记号 `void` 的宏也识别 `nothing`。因此下列三类检查不可混用：

| 层次 | 例子 | 能回答的问题 |
|---|---|---|
| 记号 | `CMETA_PP_IS_VOID(x)` | 记号是否属于规定的集合 |
| 编译器本地类型 | `CMETA_NATIVE_TYPEOF`、`CMETA_SAME_TYPE` | 表达式和声明的 C 类型是否相容 |
| CMeta 描述 | `CMETA_TYPEOF(T)` | 选择哪份可共享的类型描述 |

空可变参数同样需要能力边界。`CMETA_HAS_VA_OPT` 控制相应的零参数安全入口；不具备该能力的严格 C11 使用方采用文档规定的显式计数形式。`CMETA_PP_UNIQUE` 解决局部生成名字的冲突，不是跨翻译单元的稳定类型标识。翻译单元是一个源文件完成头文件展开等预处理后交给编译器的单位。

## 3. 泛型生成具体类型和薄包装

以下片段需要 SDK 中已注册的泛型种类，未知种类应被拒绝：

~~~c
cmeta_type(List, IntList, int);
cmeta_type(Vec, IntVec, int);
~~~

生成后的调用仍使用具体 C 名字和参数类型。**外观包装（typed façade）**负责类型检查及转发，共享实现负责分配、增长或移动算法。下面是这种包装的教学形状，`list_push_raw` 和字段 `raw` 是示意名称，不是要求读者直接调用的固定入口：

~~~c
static inline cmeta_status
IntList_push(IntList *self, int value)
{
    return list_push_raw(
        &self->raw,
        &value,
        sizeof(value),
        CMETA_TYPEOF(int));
}
~~~

包装把 `value` 的地址传给共享算法时，该地址只在当前调用期间有效。共享实现若需要保留元素，必须在返回前按元素类型契约完成复制或转移，不能保存这个局部参数的地址。因此“宏生成了有类型的接口”并没有免除元素生存期责任。

大型算法是否共享还要由生成结果验证。比较多种类型实例的预处理输出和目标文件大小，可以区分“每种类型一个短包装”和“每种类型复制整套实现”。

## 4. 从同一字段声明生成结构与描述

下面两段是替代写法，不应在同一作用域重复定义 `User`。普通 C 定义只在需要共享字段事实时才值得提升为生成声明。

~~~c
typedef struct User {
    int id;
    double score;
} User;
~~~

~~~c
cmeta_struct(User,
    cmeta_field(int, id)
    cmeta_field(double, score)
);
~~~

同一组 `cmeta_field` 行产生本地字段及反射信息。检查应对应真实成员类型、偏移和大小。若对象大小为 `S`、字段偏移为 `o`、大小为 `s`，安全的范围判断先要求 `o <= S`，再要求 `s <= S - o`；直接计算 `o + s` 可能在检查前溢出。布局范围成立仍不证明字段值已经初始化。

已有类型可以保留原定义，另行投影需要反射的字段：

~~~c
typedef struct Account {
    int id;
    double balance;
} Account;
~~~

~~~c
cmeta_reflect_data(Account, "app.Account",
    cmeta_field(int, id)
    cmeta_field(double, balance)
);
~~~

这只提供选定字段的描述，不取得 `Account` 对象的所有权，也不允许序列化器猜测未描述字段的含义。描述符与本地声明不一致应在可检查的边界拒绝。

## 5. 特征声明把能力与回调连接起来

**特征（trait）**描述类型支持的操作，例如相等比较和哈希。将能力位和函数地址分开维护，容易出现“声称可哈希却没有哈希回调”。一行声明应同时产生二者：

~~~c
cmeta_traits(User,
    (equal, user_equal),
    (hash, user_hash)
);
~~~

此片段假定 `user_equal`、`user_hash` 已按所需签名声明。生成器可以检查重复特征、未知特征和回调类型；它不能仅凭签名证明行为规律。例如哈希表还要求若 `equal(a,b)` 为真，则 `hash(a) == hash(b)`。字符串相等函数忽略大小写而哈希函数保留大小写，就是签名正确、行为不相容的反例。

## 6. 有限类型关系要求唯一匹配

有些共享事实是输入类型与结果类型的对应关系。下面的四行声明是一个有限表，不是任意隐式转换系统：

~~~c
TypeFunction(CommonArithmetic,
    (int, int, int),
    (int, double, double),
    (double, int, double),
    (double, double, double)
);
~~~

~~~c
typedef TypeEval(CommonArithmetic, int, double) result_type;
~~~

第二段得到 `double`。固定实现把每行展开为由输入记号命名的 `typedef`，`TypeEval` 拼接并引用这个名字，不在运行时遍历表。因此键 `int` 与一个恰好等价于 `int` 的 typedef 名不会自动变成同一个记号。下面的查找伪代码说明一个无重复关系表的数学要求，并不是该宏的执行实现。

~~~text
lookup(relation, left, right):
    matches = rows whose two input types match
    if matches is empty: reject unsupported input
    if matches contains more than one row: reject ambiguity
    return the sole row's result type
~~~

**唯一性推导。** 对无重复定义，每一输入对最多出现一次；查找又要求至少出现一次，两项条件合起来得到恰好一个结果。实际宏中，缺少键会引用未声明类型，冲突结果会产生不相容的 typedef；C11 允许同作用域内重复声明同一非变长类型的 typedef，因此不能宣称宏也必然拒绝结果相同的重复行。若项目要求所有重复都报错，应由 schema 检查器另行验证。需要运行时推断时，可以从同一事实源显式生成推断表；编译期入口本身不因此拥有运行时注册表。

## 7. 结构化身份不依赖描述符地址

设 `Atom(id)` 表示命名基本类型，`Apply(k,args)` 表示构造器应用。对有限无环树，下面的教学比较只使用稳定标识和子身份，不读取描述符的存放地址。

~~~text
same_type(a, b):
    if a.kind != b.kind: return false
    if a.kind == ATOM: return a.stable_id == b.stable_id
    if a.constructor_id != b.constructor_id: return false
    if a.argument_count != b.argument_count: return false
    for each corresponding pair (x, y):
        if not same_type(x, y): return false
    return true
~~~

假设稳定标识在命名域中无冲突，以树高归纳即可证明：基本类型由标识决定，构造类型由构造器及逐项相等的参数决定。复制或移动描述符不改变这些比较，所以不同翻译单元可以表达相同类型。这个模型不处理循环描述，也不从身份相等推出布局、ABI 或清理协议相同；依赖这些性质的使用方必须另行检查。

## 8. 证据与小结

将每个声明对应到一个成功例和一个拒绝例：列表上限、空参数、错误字段类型、重复特征、未知泛型以及结果冲突的类型关系。`cc -E` 检查生成的原型和元数据；跨翻译单元测试检查描述符地址不同而语义关系正确；布局与回调测试检查描述事实和真实对象一致。

CMeta 在这里复用的是有限映射、分隔和元组投影。泛型、结构体、特征和类型关系分别保留自己的语义检查。代码生成减少重复事实，唯一匹配与结构化身份解释何时可以安全共享这些事实，而运行时对象的生存期仍由真正的所有者负责。
