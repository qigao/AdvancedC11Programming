# 第七章：从计算图到执行计划：优化与直接执行

图执行器可以逐值查询节点和边，也可以在执行前把这些关系解析为计划。后者把结构检查和处理值的成本分开，但不会自动消除所有间接调用、内存操作或生命周期检查。本章说明规范化、优化和计划编译的职责，给出 Direct 的真实支持范围，再推导并行归约和成本摊销的条件。

## 1. 规范化与优化产生独立产物

第四章的图可能含有便于构造的表层算子。规范化把它们整理成后续阶段接受的基本形式；优化再对其中满足条件的结构应用改写。源图在每次变换期间保持不变，目的对象独立构造，失败时按 API 清理。

~~~text
prepare(surface):
    validate surface
    normalized = normalize(surface)
    validate normalized
    optimized = clone or rewrite normalized
    for each candidate in a finite worklist:
        if shape and metadata and authorized law all match:
            replace the candidate and record the rewrite
        otherwise:
            keep the candidate unchanged
    validate optimized
    return optimized with its trace
~~~

工作表（worklist）是待处理候选项的集合。这里强调有限处理：规则若反复生成自身可匹配的结构，优化器还需要终止度量或次数上限，不能把“循环直到没有变化”直接当作必然终止的证明。规范化不应提前读取源数据、请求订阅需求或推进执行器。

本版 `cflow_graph_normalize(dst, src)` 使用独立目的对象。用户的表层图、规范化图与优化图各自有身份，不能把其中任意一份的版本号附在另一份产物上。第六章的改写记录负责连接具体的输入与输出。

## 2. 计划把哪些查询移到编译阶段

**Lowering（具体化转换）**把较抽象的表示转换为更接近执行的表示。本章的计划编译预先解析拓扑、执行处理函数、类型和调用信息。下面是教学结构，不是 `cflow_plan` 的公开布局。

~~~c
typedef struct book_instruction book_instruction;
typedef int (*book_handler)(const book_instruction *, void *);

struct book_instruction {
    book_handler execute;
    size_t input_slot;
    size_t output_slot;
    const void *static_data;
};

typedef struct book_plan_view {
    const book_instruction *code;
    size_t count;
} book_plan_view;
~~~

在已验证计划和有效帧的前提下，教学执行循环为：

~~~c
int book_execute(const book_plan_view *plan, void *frame)
{
    for (size_t i = 0; i < plan->count; ++i) {
        const book_instruction *insn = &plan->code[i];
        int status = insn->execute(insn, frame);
        if (status != 0)
            return status;
    }
    return 0;
}
~~~

这里只展示预解析分派：`execute` 已确定，槽位已分配，循环不必查找图边。实际计划还需处理终端、值所有权和失败清理；一段线性循环不能代替这些实现。**热路径（hot path）**是反复处理输入值的执行部分，编译前移的是结构查询，不是所有运行时义务。

固定快照的 `cflow_plan_compile` 接受已经规范化的基本图；`cflow_plan_compile_surface` 提供表层图的便捷入口。计划执行不再查询 Graph、Node、Edge 或 Subgraph 的拓扑。顺序物化执行既可支持平凡值，也可支持具备相应复制、移动和销毁特征的值，不能把它整体描述为“每次执行都不分配”。

## 3. 执行存储与失败清理

`cflow_plan_eval_array` 借用输入，成功输出独立拥有其返回值，使用方调用 `cflow_result_destroy` 释放结果。若使用可复用工作区，则需要遵循另一组契约：

| 对象或入口 | 固定快照的限制 |
|---|---|
| `cflow_plan_batch_workspace` | 仅支持具备规范批量调用入口且值存储平凡的融合计划 |
| 初始化 | 预分配最多指定数量输入所需的暂存空间 |
| 工作区求值 | 不进行堆分配或释放；输入数量不得超过容量 |
| 工作区结果 | 借用工作区，下次求值或销毁时失效，不调用 `cflow_result_destroy` |
| 并发使用 | 工作区单所有者，不能同时用于两次求值 |

这些条件说明“分配在前”是某个已准入路径的性质。把工作区结果存到异步任务里，需要先复制到适当的自有存储或延长整个工作区独占区间。仅复制结果结构中的指针不会取得值的所有权。

## 4. Direct 支持的计算形状

AOT 是 ahead-of-time（提前编译），说明代码在执行前生成和编译。Direct 描述执行形式。本版 Direct 使用最多十六个 Filter/Map 阶段；完整的 Filter、Map、Reduce 管道应使用受支持的 Plan 路径。

以下声明片段使用第五章定义的、元数据满足条件的 `sample_even` 和 `sample_square` 可调用对象，并需要 `<cflow/direct.h>`：

~~~c
#define EvenSquareSteps(M) \
    CFlowDirectSteps(M, \
        (filter, int, int, sample_even), \
        (map, int, long, sample_square))

cflow_direct_pipeline(even_squares,
    int, &cmeta_type_int, long, 2, EvenSquareSteps);
~~~

宏生成构图、阶段描述、资格检查和数组执行入口。这里输出平方序列，例如六个输入得到 `{4, 16, 36}`，尚未归约为 `56`。生成的数组执行入口要求完整输出容量至少等于输入数量；它不会先运行谓词来猜测最终需要多大空间。

资格检查要求类型具备平凡复制与销毁，调用可绑定、无捕获，效果为 PURE，性质包含 DETERMINISTIC、TOTAL 和 NO_ALIAS，并且每一步的签名与类型链相容。Filter 返回 `bool` 且保留值流类型，Map 的输出也必须适合 Direct。第五章的有限数值域仍是平方函数正常定义的前提；元数据标志不能扩展 `long` 的范围。

阶段 IR 还区分静态目标、规范批量入口和适配入口。只有全为静态目标的适合路径才能生成直接命名的 C 调用；这也不保证 C 编译器最终把函数体内联到机器码中。

## 5. Direct 的拒绝条件

生成的数组路径检查输入、完整输出容量和结果计数存储的范围，拒绝溢出的字节数计算及不允许的重叠。它不进行分配、调度或间接阶段回调；失败返回对应 Direct 状态，不自行转入 Plan。

~~~text
evaluate_direct(inputs, count, outputs, capacity, written):
    validate byte ranges and required disjointness
    set written to zero
    reject an ineligible schema
    reject capacity < count
    for each input in encounter order:
        apply the statically named Filter/Map stages
        append each surviving output
    commit written count
~~~

这是控制流摘要，不能把“范围检查通过”理解为证明任意非空地址都指向真实 C 对象。存储必须由调用者提供并保持有效。若范围检查本身失败，实际入口在写入 `written` 之前返回；不能承诺任意无效计数指针都被清零。

## 6. 有序并行归约的推导

并行归约保留语义算子，改变执行的分组方式，属于执行精化。设二元运算 `⊕` 对允许的值满足结合律 `(a ⊕ b) ⊕ c = a ⊕ (b ⊕ c)`，且没有可观察副作用和失败。把输入切成连续非空块，按块内原序归约，再按块的原序合并，就只改变括号位置，没有交换元素。

~~~text
ordered_reduce(values, chunks):
    require valid nonempty contiguous chunks
    require a homogeneous, pure, total associative reducer
    submit one admitted reduction task for each chunk
    collect chunk results into their original positions
    combine those results in chunk order
~~~

按结合律反复移动括号，可将分块表达式还原为顺序表达式，因此结果相同。这里不需要交换律，不能按任务完成的先后随意合并。带初值的处理还须保证初值的出现次数符合原语义，不能无条件在每个块前重复插入一个非单位元。

数学整数加法的结合律不能直接证明任意 C 有符号加法安全。偶数平方和的各项非负，总量已受界，因此任何连续分组的中间和都不超过总量；这个域内重分组不会溢出。浮点加法通常不满足精确结合律，不能仅设置 ASSOCIATIVE 标志就获得相同位结果。

实际并行 Plan 还要求受支持的平凡存储、具备所需并发能力的执行器、有效任务与块边界，以及完整的准入条件。不支持的计划、非空块不足、无效选项或任务被拒绝都会显式失败，不自动顺序重试。

## 7. 证书绑定计划与图

**证书（certificate）**在这里是可检查的执行对应记录，不是密码学签名。固定快照的计划证书保存路径、顺序模型、所需能力、图版本、指纹，以及逐条操作、类型、调用和参数信息。

~~~text
check_certificate(certificate, graph, plan):
    require a supported certificate version and execution path
    require matching graph identity and structure
    require every recorded row to match graph and plan semantics
    require the requested order and capabilities
    accept only after all rows match
~~~

图版本帮助拒绝修改前的旧记录；指纹帮助绑定结构，但不是抗恶意碰撞的签名。含指针的证书行是进程内执行证据，不能直接持久化为跨进程格式。相关 Lean 证书定理证明模型中的行对应与观察保持，C 检查器、内存生存期和工具链仍需要工程验证。

实现依据 [plan.h](https://github.com/qigao/salts/blob/a650262031e9b3e5f11a227a7911a75db9ae1fb8/cflow/include/cflow/plan.h)、[direct.h](https://github.com/qigao/salts/blob/a650262031e9b3e5f11a227a7911a75db9ae1fb8/cflow/include/cflow/direct.h) 与 [certificate.h](https://github.com/qigao/salts/blob/a650262031e9b3e5f11a227a7911a75db9ae1fb8/cflow/include/cflow/certificate.h)。它们同时给出资源与失败契约，不能只依据成功路径设计调用方。

## 8. 计算成本何时可以摊销

设新增的计划准备成本为 `B`，同一批输入解释执行一次成本为 `I`，计划执行一次为 `P`，重复执行 `k` 次。计划更便宜的条件为 `B + kP < kI`。只有 `I > P` 时，才能整理为 `k > B / (I - P)`；否则增加重复次数也不能收回准备成本。

这是一项成本模型，不是测量结果。实际报告应分别记录构图、规范化、优化、编译、执行、工作区字节数和代码大小，并区分“每请求重建计划”与“多请求复用计划”。平凡整数、托管值、短输入和长输入应分别测量，不能把某条工作区路径的结果推广到所有计划。

## 9. 小结

计划编译提前解析结构，Direct 在更严格的条件下生成直接调用，工作区把特定路径的分配前移。并行归约依赖值域、结合律、顺序和资源条件；证书把执行产物与具体图连接。支持范围、失败返回与成本测量共同决定应选择哪条路径，不能由图合法性或一个性质标志代替。
