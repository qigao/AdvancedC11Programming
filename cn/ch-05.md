# 第五章：Stream 接口：构造有类型的计算图

过滤、映射和归约常常一起出现。普通 C 循环已经能完成这些操作；Stream 的用途是把操作组合保存为可检查、可重复使用的计算描述。本章沿用偶数平方和的例子，从循环推导类型连接和构图算法，再检查接口构造是否保持原有含义。CMeta 在这里提供可调用对象的类型、签名和性质声明，CFlow 用这些事实建立计算图。

**外观接口（façade）**是在已有机制上提供较方便的调用方式。本章的 Stream 是计算图的外观接口：调用 `filter` 或 `map` 时追加图节点，实际遍历发生在执行阶段。**可观察语义（observable semantics）**指契约允许调用者观察到的结果，包括输出值、顺序和错误；判断两种写法是否等价，必须先说明比较这些结果中的哪些部分。

## 1. 从可运行的普通 C 程序开始

下面是完整的 C11 程序，保存为 `stream_baseline.c` 即可编译。输入中的偶数为 2、4、6，平方后相加得到 56。若把辅助函数用于其他输入，本例要求 `n <= 1000`、每个元素位于 `[-100, 100]`，且 `xs` 指向至少 `n` 个可读的 `int` 对象。这些限制保证平方和不超过 10,000,000，处于 C11 要求的 `long` 最小可表示范围内；不能把强制转换为 `long` 当成对任意输入都不溢出的证明。

~~~c
#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>

static bool is_even(int x) { return x % 2 == 0; }
static long square(int x) { return (long)x * (long)x; }

static long even_square_sum(const int *xs, size_t n)
{
    long total = 0;
    for (size_t i = 0; i < n; ++i) {
        if (is_even(xs[i]))
            total += square(xs[i]);
    }
    return total;
}

int main(void)
{
    const int xs[] = {1, 2, 3, 4, 5, 6};
    printf("%ld\n", even_square_sum(xs, sizeof xs / sizeof xs[0]));
    return 0;
}
~~~

~~~bash
cc -std=c11 -Wall -Wextra -Werror -pedantic stream_baseline.c -o stream_baseline
./stream_baseline
~~~

**循环不变量。** 进入第 `i` 次迭代时，`total` 等于前 `i` 个元素中所有偶数的平方和。初始时 `i = 0`，空前缀的和为零。不满足谓词时，前缀增加一个不参与求和的元素；满足时，程序恰好加入该元素的平方，所以不变量在下一次迭代仍成立。循环结束时 `i = n`，得到整个输入的结果。这是对所示循环的手工推导，依赖有效存储和上述整数范围。

## 2. 用 CMeta 描述三个可调用对象

以下片段使用固定快照中的宏和 Stream 入口；它依赖已安装的 CMeta/CFlow SDK，不是上面程序的独立替换文件。`cmeta_function` 除了产生具体函数，还提供带操作类别的可调用对象。构图时传入的是这些对象，签名事实因而可以被统一检查。

~~~c
#include <cflow/cflow.h>

cmeta_function(filter, value, bool, sample_even, (int x)) {
    return x % 2 == 0;
}
cmeta_function(map, value, long, sample_square, (int x)) {
    return (long)x * (long)x;
}
cmeta_function(reduce, associative, long, sample_add,
               (long left, long right)) {
    return left + right;
}

static bool build_pipeline(cflow_stream *s)
{
    if (!cflow_stream_init(s, &cmeta_type_int))
        return false;

    s->filter(s, sample_even);
    s->map(s, sample_square);
    s->reduce(s, sample_add);
    return cflow_stream_ok(s);
}
~~~

调用方须提供一个尚未初始化的 `cflow_stream`，例如 `cflow_stream s = {0};`。构图成功后使用 `cflow_stream_graph(&s)` 取得只读借用视图，使用结束后调用 `cflow_stream_destroy(&s)`；初始化成功后即使后续构图失败，也须销毁已取得的图资源。不要在仍持有资源的 Stream 上重新调用初始化函数。

这里的 `associative` 是结合律声明，意为在适用域内 `(a + b) + c = a + (b + c)`。宏不会替函数体证明这条性质。对任意有符号整数，溢出会使这个声明失去依据；对本例范围内的非负平方项，任一部分和都不超过总和，重新分组仍在可表示范围内。若把 `sample_add` 用于其他输入，必须重新检查适用域。

三个方法调用之后仍要检查 `cflow_stream_ok`。固定实现会记录失败，并可能继续返回同一个非空 Stream 指针；因此“返回非空”不能替代整个构图是否成功的检查。将调用写成链式只改变书写形式，不会改变这一错误约定。

## 3. 类型连接与构图算法

**谓词（predicate）**是返回布尔值的函数；**归约（reduce）**把多个值逐步合并为至多一个结果；**输出数量关系（cardinality）**描述一次输入会产生多少个输出。下表只讨论本例的顺序执行和未设置初始种子的归约。

| 操作 | 要求的函数签名 | 图中的类型变化 | 输出数量关系 |
|---|---|---|---|
| Filter | `T -> bool` | `T -> T` | 每个输入产生零或一个值 |
| Map | `T -> U` | `T -> U` | 每个成功处理的输入产生一个值 |
| Reduce | `(T, T) -> T` | `T -> T` | 非空输入归约为一个值；空输入没有累计值 |

`T`、`U` 是类型变量，箭头表示函数的参数类型与结果类型；它不表示资源所有权转移。固定快照的普通 Reduce 要求输入、累计值和结果为同一种类型。因此本例先把 `int` 映射为 `long`，再调用 `(long, long) -> long` 的加法。更一般的 `(A, T) -> A` 折叠需要另行定义接口与规则，不能直接冒充当前入口。

下面的伪代码概括 `stream.c` 中的调用顺序。bind 在这里表示校验并取得可用的调用描述，不表示执行用户函数；节点连接、类型检查和容量约束继续由 Graph 处理。

~~~text
append(stream, operator, callable):
    if stream has a recorded failure: return stream
    bind and validate the callable's signature and contract
    if binding fails: record failure; return stream
    ask Graph to check and append this operator
    if Graph rejects it: record failure
    return stream
~~~

成功追加一个 Filter 后，尾节点类型仍为 `T`；成功追加 Map 后，尾节点类型变为函数结果 `U`；后续 Reduce 只接受 `(U, U) -> U`。例如 `int -> long` 的 Map 后若接 `(double, double) -> double` 的 Reduce，构图应拒绝这次组合。类型名字在文档里看起来相近没有帮助，检查依据是 CMeta 的类型与调用契约。

失败后不能执行这个 Stream。伪代码只承诺记录失败，不承诺每一种底层失败都把图恢复到调用前的字节状态；需要事务式构图时，应另有明确的暂存、提交与回滚协议。

## 4. 构图为什么保持计算含义

设 `ops` 是按顺序给出的操作列表，`Build(ops)` 是接口成功构造的图。记 `Obs(P, xs)` 为程序 `P` 在输入 `xs` 上按契约产生的输出序列、完成或错误结果及其先后顺序。对于合法输入，接口应满足：

~~~text
Obs(Stream(ops), xs) = Obs(Graph(Build(ops)), xs)
~~~

这是本节的证明目标，不是已经机器检查过的定理。对成功追加的操作数作归纳：没有操作时，两边使用同一个输入协议；追加一个操作时，接口把相同的操作码和同一可调用对象交给 Graph，没有额外调用用户函数，也没有改写输入顺序。假设前缀的观察结果相同，新增节点便接收相同的前缀输出，并按同一规则产生后续观察结果。归纳结论成立的前提是接口不另设隐式缓冲、错误吞没或后端替换规则。

这个构图推导不自动证明某次图优化合法。比如删除一次 Map 会改变函数调用次数；若函数记录日志，即使最终数值相同，调用者仍可观察到区别。优化需要第六章的额外语义条件，执行后端也必须通过第七章的支持范围检查。

与第 1 节的循环比较时还要处理空输入。该循环把空输入或全被过滤的输入归约为零；本节未设置种子的 Reduce 没有任何输入值时没有累计结果。因此，结果均为 56 的比较针对所给非空过滤结果，不能由此声称两个接口对所有输入相同。要采用“空和为零”的约定，应使用有明确初值语义的入口，并把该语义纳入证明。

## 5. 输入借用与每次执行的状态

**范围视图（Range）**描述怎样遍历一段输入，例如保存对象地址、元素类型和取得下一个元素的方法。复制视图只复制这些描述，不延长底层数组或容器的生存期。**收集器（Collector）**规定怎样把输出写入目标对象；目标存储及其提交、失败处理仍须遵守对应契约。

| 对象 | 保存的事实 | 生存期要求 |
|---|---|---|
| Stream / Graph | 操作、类型、连接与不可变参数 | 使用借用图视图期间，原描述仍须有效 |
| Range | 输入对象与遍历协议 | 底层对象在遍历期间有效；可重复遍历须由 Range 契约允许 |
| 单次执行 | 游标、累计值、计数器和临时值 | 执行结束或取消时按协议清理 |
| Collector | 输出写入及提交规则 | 被借用的输出对象和上下文覆盖执行及清理 |

同一描述执行两次时，每次都需要新的累计值。若第一次得到 56，第二次从 56 开始累加就会得到 112；这不是输入变化，而是把活动执行状态误放进了共享描述。跳过数量、已取得数量和等待登记也有同样的问题。描述可重用只说明图结构可重用，不保证任意一次性 Range 都能重新开始，更不自动授予多个线程并发遍历同一输入的权限。

异步收集进一步延长借用期。固定快照的 `cflow_stream_execution_start` 创建自己的规范化图、订阅和收集器状态，但借用调度器、Range 底层对象及收集器的有关上下文直到销毁完成；该入口要求调度器声明并发能力。启动成功后离开保存输入的栈帧，仍会产生悬空借用。

## 6. 从一份操作表生成普通 C 接口

`CFlowOperators` 把操作种类、函数参数角色、输出规则等写在同一份声明中。`Replay(CFlowOperators, consumer)` 将规范化后的每一行交给不同的使用方，生成方法类型、结构字段、初始化赋值和构图包装函数。这里使用的是第二章的有限表展开：同一个 Filter 声明不必在四处手工保持一致。

下面是 Filter 方法有关声明的教学展开，三个部分分别位于类型声明、结构体和初始化函数中，并非可以按原样拼接的独立翻译单元：

~~~c
typedef cflow_stream *(*cflow_stream_filter_method)(
    cflow_stream *self, cflow_filter_callable fn);

/* Field generated inside struct cflow_stream: */
cflow_stream_filter_method filter;

/* Assignment performed during initialization: */
s->filter = cflow_stream_filter;
~~~

`s->filter(s, sample_even)` 仍是一次普通 C 函数指针调用。显式传入的 `s` 是接收者，初始化后的字段选择对应构图函数；该函数再取出可调用对象中的签名和类型事实，交给 Graph 校验。宏消除重复声明，类型描述符支持构图检查，函数指针保留普通 C 调用方式，各自完成不同工作。

结构中能看见某个字段，并不意味着使用方可以任意写它。固定头文件把生成的方法字段作为稳定调用入口，把图作为高级只读检查对象，把 `input_range`、`eval_options` 和失败状态等列为内部字段。优先通过 `cflow_stream_graph` 观察图，避免绕过构图函数改写节点。

## 7. 用实现证据检查边界

本章具体接口以 [stream.h](https://github.com/qigao/salts/blob/a650262031e9b3e5f11a227a7911a75db9ae1fb8/cflow/include/cflow/stream.h)、[stream.c](https://github.com/qigao/salts/blob/a650262031e9b3e5f11a227a7911a75db9ae1fb8/cflow/src/stream.c) 和 [operators.h](https://github.com/qigao/salts/blob/a650262031e9b3e5f11a227a7911a75db9ae1fb8/cflow/include/cflow/operators.h) 为依据；异步借用约定见 [stream_execution.h](https://github.com/qigao/salts/blob/a650262031e9b3e5f11a227a7911a75db9ae1fb8/cflow/include/cflow/stream_execution.h)。这些链接均指向 `SOURCE_SNAPSHOTS.md` 规定的固定版本。

[证书测试](https://github.com/qigao/salts/blob/a650262031e9b3e5f11a227a7911a75db9ae1fb8/cflow/tests/cflow_certificate_test.c) 使用过滤偶数、映射平方、归约相加的相同组合，随后规范化图、优化图、编译计划并构造和检查证书。**证书（certificate）**在这里记录图与计划对应的可检查事实；检查成功不等于机器已经证明任意 C 函数体满足作者声明的结合律。测试还会篡改记录中的字段以验证拒绝行为，应把这些反例与成功路径一起阅读。

| 检查对象 | 应观察到的结果 | 不能据此推出的结论 |
|---|---|---|
| 错误的谓词或归约类型 | 构图失败，错误可查询 | 所有运行时对象地址都有效 |
| 相同描述重复执行 | 每次使用独立的活动状态 | 同一 Range 总能并发或重复遍历 |
| 指定后端不支持该图 | 明确拒绝，不静默更换后端 | 合法图一定能用任意后端执行 |
| 证书字段被篡改 | 对应检查拒绝 | 用户函数体的数学性质自动成立 |

第 1 节的循环也是性能基线。测量时分别记录构图与执行时间，固定输入、操作、结果检查和后端，再比较重复执行的成本。Direct 指减少逐值解释的直接执行路径；AOT（ahead-of-time）指运行前生成并编译代码。固定快照的 Direct 支持范围主要是 Filter/Map，不能把上面的完整归约循环说成已经由 Direct 生成。含 Reduce 的计划执行及其资格条件见第七章；本章不从接口写法推导性能数字。

## 8. 小结

Stream 把 CMeta 的函数与类型事实用于计算图构造。方法追加节点，Graph 校验连接；输入仍由原对象持有，每次执行另外保存游标和累计状态。证明接口保持含义，需要逐项对应操作、调用对象和观察结果，并处理初值、空输入、失败与后端支持范围。这样，方便的调用形式、可检查的图描述和最终普通 C 执行之间才有明确对应关系。
