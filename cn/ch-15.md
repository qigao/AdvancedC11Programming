# 第十五章：CMeta 综合应用：从声明事实到可靠执行

前面的章节分别建立了宏展开、函数适配、图变换和异步执行的条件。本章把它们用于一个受界的计算服务：接收一批整数，返回偶数平方和。先给出完整普通 C 程序，再逐项增加契约绑定、可复用计划和异步交接，检查每次增加机制后哪些前提必须保留。

## 1. 可以独立运行的基线

程序接受最多一千个 `[-100, 100]` 内的整数。成功返回总和，空输入返回零；任何参数或值域错误都保留原响应。请求与响应及其所指数组必须是有效对象，且响应不与输入存储重叠。

~~~c
#include <stddef.h>
#include <stdio.h>

enum {
    BOOK_OK = 0,
    BOOK_INVALID_ARGUMENT = 1,
    BOOK_OUT_OF_RANGE = 2,
    BOOK_MAX_ITEMS = 1000
};

typedef struct BookRequest {
    const int *values;
    size_t count;
} BookRequest;

typedef struct BookResponse {
    long total;
} BookResponse;

int book_score(const BookRequest *request, BookResponse *response)
{
    if (request == NULL || response == NULL)
        return BOOK_INVALID_ARGUMENT;
    if (request->count > BOOK_MAX_ITEMS ||
        (request->count != 0 && request->values == NULL))
        return BOOK_INVALID_ARGUMENT;

    long total = 0;
    for (size_t i = 0; i < request->count; ++i) {
        int x = request->values[i];
        if (x < -100 || x > 100)
            return BOOK_OUT_OF_RANGE;
        if (x % 2 == 0)
            total += (long)x * x;
    }

    BookResponse next = { .total = total };
    *response = next;
    return BOOK_OK;
}

int main(void)
{
    const int values[] = {1, 2, 3, 4, 5, 6};
    BookRequest request = {
        .values = values,
        .count = sizeof(values) / sizeof(values[0])
    };
    BookResponse response = { .total = -1 };
    if (book_score(&request, &response) != BOOK_OK)
        return 1;
    printf("%ld\n", response.total);
    return response.total == 56 ? 0 : 1;
}
~~~

按 C11 编译运行，程序打印 `56`。这里使用 `long` 保存平方和，`int` 返回独立状态；不要把业务总和塞进状态返回值，也不要以 `-1` 同时表达所有错误和合法计算结果。

## 2. 基线的正确性与失败边界

在处理第 `i` 项之前，已处理的值都在允许域内，`total` 等于其中偶数的平方和，并满足 `0 <= total <= 10000i`。初始零项时成立。新输入越界则直接失败，响应尚未写入；合法奇数保持总和；合法偶数增加至多一万，因此不变量保持。

`i <= 1000` 给出总量至多一千万，C11 的最小 `long` 范围已足够。最后一次结构赋值才发布结果，所以参数错误或中途越界都不改变响应。输入 `{2, 101}` 必须失败并保留原响应，不能返回先算出的四；空输入则成功提交零。

这个证明只涉及本地同步调用。输入指针必须在整个调用期间有效且没有数据竞争，`const` 不会冻结另一个线程正在修改的数组。后续所有适配路径都必须保留这些前提，或者在边界处建立等价的自有副本。

## 3. 从 C 类型到共享函数契约

若只有 `main` 调用，基线已经完整。需要外部绑定、生成 Mock 或动态发布时，CMeta 才需要描述 `BookRequest`、`BookResponse` 和 `book_score`。描述至少记录请求为输入借用、响应为输出借用，以及返回 `int` 为值状态。

| 已有事实 | CMeta 中的用途 | 仍需应用说明的内容 |
|---|---|---|
| 请求与响应的 C 类型 | 数据描述与本地 ABI | `values` 指向 `count` 个活动元素 |
| 函数参数和返回类型 | FunctionDesc 与 FunctionAbi | 数值域、数量上限和状态含义 |
| 统一执行入口 | 显式生成的 exact thunk | 存储类型、对齐和生存期 |
| 提供方上下文 | 明确借用或接口实例 | 生命周期与并发访问规则 |

指针字段的反射不会自动产生数组长度关系。数据模型必须明确把 `values` 与 `count` 关联，或使用生成器支持的序列表示；不能仅反射两个字段就宣称已经得到安全的网络解码器。类型集合与 ABI 注册也必须符合第二、三章的有限规则。

调用适配器的证明可以复用第三章：准入失败不调用目标；存储正确且准入成功时调用具体函数一次。这里还需继承第二节的值域检查，才能证明目标函数的成功结果。

## 4. 外部服务契约与本地表示

逻辑请求可以描述为“最多一千个有界整数”，响应为总和，错误区分无效参数和值域不符。这个逻辑序列不包含本地指针；DataBind 投影负责将传输数据转换成拥有明确生命周期的本地存储。

~~~text
admit_score_service:
    resolve the logical request, response, and error contract
    match the generated native layout and exact function ABI
    require a supported bounded sequence representation
    compile ingress, egress, and error mappings
    retain descriptor/code owners for the service lifetime
~~~

这是集成设计伪代码，不是宣称任意当前 HTTP 后端已经支持该序列。第八章核对过固定 CHttp 快照的结构化输入输出限制；不满足支持范围时，在挂载前拒绝，保留普通 C 入口用于本地调用与基线测试。

`get_user` 的仓库注入与这里的序列存储是同一类边界问题：逻辑契约描述交换的数据，本地绑定另行决定依赖从哪里来、存储由谁拥有。不能把 C 参数列表机械变成网络字段。

## 5. 可复用计算计划

若系统要反复执行并比较多种管道，可把计算表示为 Filter、Map 和有初值归约。归约前的域检查仍需保留；它可以在输入准入阶段进行，不能因为 PURE/TOTAL 标志已经设置就删除检查。

~~~text
prepare_computation:
    describe is_even: int -> bool
    describe square: int -> long over the admitted domain
    describe sum: (long, long) -> long over bounded nonnegative totals
    build and validate the typed graph with zero seed
    normalize and apply only authorized rewrites
    compile the explicitly selected supported Plan

evaluate_computation:
    validate input count and every input value
    borrow or own the accepted array for the entire evaluation
    execute the reusable plan
    commit one result or report failure
    destroy the owned result at its documented boundary
~~~

有初值归约与基线一样在空输入得到零。若选择第五章的无初值 Reduce，应在调用方把“没有归约值”显式解释为零，并把这个决定纳入比较。包含 Reduce 的整条管道不属于第七章固定版 Direct 的 Filter/Map 支持范围。

计划保持类型链和求值语义，基线证明还提供数值范围。两者合在一起，才能比较具体结果。若新增日志回调或托管资源，观察模型随之改变，原先只比较数值的证明不能直接授权删除、重排或重试这些调用。

## 6. 延迟任务如何取得有效输入

同步函数借用栈上的数组没有问题，前提是调用结束前栈仍在。把 `BookRequest` 按字节复制到任务里只复制指针和数量，原数组可能在任务运行前消失。延迟执行需要独立的受界请求帧，或者明确持有上层输入所有者。

~~~text
submit_score(request):
    validate count and values
    acquire an owned bounded frame
    copy the admitted array into the frame
    store result and completion state in that frame
    submit run/cancel/finalize callbacks
    if rejected:
        release the caller-owned frame
    if accepted:
        let the terminal task path release it exactly once
~~~

所有权不变量为：帧在提交前由调用方持有；拒绝后仍由调用方释放；接受后由任务终结路径负责，最后一次访问早于释放。run 可以发布一个独立拥有的响应，也可以把结果交给有明确持有协议的接收者；不能返回一个随 finalize 立即释放的指针。

若执行入口或清理函数来自 Plugin，外层租约还必须覆盖 finalize。第十章的任务计数和第十三章的卸载顺序共同约束这条路径。一个成功的 post 返回既不等于结果完成，也不保证上下文尚未被终结。

## 7. 持续输入需要响应式协议

批量请求结束后就有最终结果；持续输入可能暂时没有值。此时引入第九章的 VALUE、WAIT、DONE、ERROR，以及订阅需求额度和等待登记。WAIT 只是一次观察，登记等待与最终休眠需要消除丢失唤醒；回调令牌也不独自保证其存储生存期。

例如需求为二，源先发出一、再发出二，Filter 只向下游传递二，因此剩余需求为一。之后源返回 WAIT，不消耗这一个额度；唤醒只触发再次推进，也不增加额度。只有另一个真正的下游输出才把额度减为零。若整条流以 Reduce 为终端，归约结果而不是每个输入元素消耗下游输出额度。

持续连接控制还可能需要 Machine 与 Actor，但计算服务本身不因此必须拥有 Actor。只有类型化事件、串行状态修改、独立生产者能力和关闭竞争成为真实需求时，才增加第十一、十二章的运行对象。

## 8. 将集成主张变成验证

| 情形 | 基线或协议要求 | 对应比较 |
|---|---|---|
| `{1,2,3,4,5,6}` | 总和 `56` | 普通 C、适配入口、受支持 Plan |
| 空输入 | 成功且总和零 | 明确处理无初值归约差异 |
| `{2,101}` | 失败且响应不变 | 输入绑定与执行均无部分发布 |
| 一千个 `100` | 一千万，无溢出 | 极限容量与值域 |
| 任务 FULL | 目标函数未执行，帧由调用方清理 | 拒绝路径计数及生存期 |
| 接受后取消 | run/cancel 互斥，finalize 一次 | 执行器协议 |
| Plugin 仍有借用 | 卸载被拒绝 | 真实动态库测试 |

同一输入和值域分别比较直接函数、thunk、Invokable、Plan 与工作区路径；只测各自支持的形状。报告准备成本、单次执行、重复执行、峰值存储和代码大小，不把普通 C 基线的正确性或某个 Lean 定理当成性能证据。

## 9. 可以独立复用的方法

本例中的每个机制都对应一个具体缺口：宏避免多份声明，CMeta 使本地事实可检查，DataBind 编译外部与本地之间的映射，CFlow 保存可分析的组合，运行对象维护不能在构建期决定的状态。引入机制前先保留普通 C 基线，写清输入、输出、失败和所有权，再给出转换或状态算法。

推导应与算法使用同一组对象：循环用前缀不变量，绑定用参数重建与存储前提，资源用已初始化集合，异步任务用状态分区。已有形式定理可以证明对应模型的结论；编译、安装、并发与测量验证实现中剩下的条件。这样得到的结论才能指导下一次代码修改。

## 10. 小结

CMeta 的高级技巧让共享事实进入可检查的声明与描述，但执行最终仍遵循具体 C 类型、对象生存期和资源契约。完整应用的可靠性来自这些边界相互对齐：输入转换建立值域，适配保持调用，计划保持计算，运行实例维持状态和单次清理。任何一层新增行为，都应同步更新例子、推导和验证。
